# Q010 v1.6 evidence and scope review

This is a read-only assessment of the supplied `Research/Q010_InferenceRecovery_v1.6_RecoveryContext.zip`. Its `REPORT.md`, `STATUS.json`, protocol locks, audit receipts and retained predecessor reports are the evidence examined. I did not execute its verifier, model, producer or training code. The compact context archive itself labels its scope `REVIEW_AND_REGENERATION_CONTEXT_NOT_FULL_RAW_EVIDENCE`: it includes the fifteen saved exports, per-query scores and receipts, but omits bulk raw main capture/replay frames and the uploaded input ZIPs. Thus its exact array comparisons and complete package verification are reported results, not independently inspected raw-array findings in this review.

## What the recovery establishes

The reported inference run binds fifteen final exports to the original *reconstructed v1.4* frozen protocol and five paired seeds (1201–1205); the original Q010 v0.1 checkpoint/source archive is still missing. The saved fit manifests report 6,000 updates each. v1.6 reports zero new optimizer updates, all 64 condition cells in each seed, 449,640 query chains, 3,045,480 logical reader stages, independent source/ledger/arithmetic/decoder scoring, and exact local CPU replay of 50,835 arrays. Its fresh score digests match the retained v1.4 reported score digests. This substantially strengthens the fixed-weight evaluation record for the reconstructed models. It does not establish how all main optimizer steps occurred: the delivered v1.5 package has zero full optimizer/RNG checkpoints and zero raw main numerical training traces, although its retained prior audit says it had checked fifteen contiguous traces. Three 6,000-step reproduction results are prior JSON reports, not fresh v1.6 reproduction. `STATUS.json` correctly sets `original_training_protocol_fully_requalified=false`.

The three archived verifier errors remain: two Windows-fixture byte-equality mismatches and one unavailable historical lifecycle fixture. The fresh 23/23 regression assertions use a newly generated development fixture. They should be reported beside, rather than added over, the archived failures.

## Acceptance meaning

All three reconstructed candidates pass the declared v1.4 pooled gates and all five individual seed screens: 0.90 applicable core classes, 0.95 direct visible-fact classes and 0.90 at each nominal cadence-8 checkpoint. This is a legitimate bounded result under that frozen reconstructed protocol. It is **not** a reversal of the lost v0.1 Qualification010 result, where the close-identity continuation passed the complete nominal screen in 0/5 pairs and direct visible-fact competence in 0/5. The predecessor report used a different original model/source and criterion set; the recovered v1.4 attention model has 86,464 parameters versus 94,728 in the lost original. The retained v1.4 `QUALIFICATION.json` explicitly describes its gates as reconstructed 0.90/0.95/0.90 criteria, not the historical 0.95 all-pair study. Comparing the words PASS/FAIL across those studies would collapse distinct estimands. Compare matched condition-level metrics instead, with provenance attached.

Passing these gates also leaves hard negatives: v1.6 reports near-model close-source supported accuracy of 229/320 (71.56%); all three candidate readers give 0/640 correct UNKNOWN responses on near-collision novel queries, 0/320 supported responses with state removed, and 0/320 after no-maintenance event 1,024. This remains a 16-record, eight-stage synthetic task with supplied identity catalogue, protected owner metadata for the privileged control, qualified writes and structured reader interfaces. Exact-owner traversal demonstrates what that scaffold can do; it does not show that a learner can infer ownership, admission or relationships from unstructured external evidence. Pooled gate success must not be presented as general identity recognition or a general architecture comparison.

The reconstructed numerical-audit underflow amendment was pinned before v1.6 integration and all-case scoring. It was built from retained rationale and adds `eta=2^-126` to the final softmax probability error bound, leaving score labels and scientific thresholds fixed. A fresh actual 128-case main batch reproduces the frozen verifier rejection and passes the amended verifier with unchanged bytes; synthetic underflow and corruption checks are retained. The original rejected raw row and original v2 verifier implementation are absent. Hence numerical acceptance is under the amended contract, while the original frozen contract did not pass unchanged. This matters for the audit claim even though it does not itself explain the candidates' behavioral scores.

## Smallest next discrimination

First use the retained per-query data to report paired per-seed close-source supported accuracy *and* novel/near-collision UNKNOWN accuracy for the same reader set, separating assisted multi-stage answers from direct no-cleanup answers. That resolves whether the near continuation's gate pass conceals the same recall-versus-rejection tradeoff observed in the predecessor, without new training. If the next Chat experiment is warranted, preregister one small new held-out close-identity and unregistered-origin challenge, hold all fifteen exports and scoring rules fixed, include the inherited and exact-owner controls, and measure the joint supported/UNKNOWN tradeoff across all five seeds. Version it as a new generalization test, not completion of missing training reproduction or the original v0.1 study.

For that challenge, the fair external gate can use the initial numerical query, valid record keys/values and their similarity or learned row/UNKNOWN logit margins. The pipeline's protected active catalogue is separately available to its common cleanup resolver, so any gate using it must be labeled catalogue-assisted. The hidden `source_id`, query recipe kind, anchor ID, graph truth and exact owner handles are verifier/control metadata, not learner inputs. In this generator, a near-novel query is a normalized small perturbation of an existing code but is labeled UNKNOWN; a close-source case instead moves an *active unrelated decoy code* near a known path source. The numerical distributions overlap, so proximity alone cannot certify origin. A useful gate must report its known-query rejection cost alongside false novel acceptance.
