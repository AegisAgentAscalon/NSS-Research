# IdentityBinding009 — resolved protocol

Local preparation/pilot followed by source/checkpoint lock on 21 September 2026.
This is not an external preregistration. The supplied v0.1 plan remains unchanged.

## Scope and input boundaries
Fixed evaluation parameters, 16 identities/record capacity, 17-coordinate numeric
identity ABI from Study006. Register/owner schema is now nbr009-owner-state-v1;
old snapshots are rejected. Relation = single location relation. No additional
major core, online optimizer, low-bit learning state, natural language, biological
simulation, target-device qualification or companion release.

## Preparation
Ten continued 818-parameter binders: ordinary extra preparation versus near-negative
preparation. Parent pairs1..5, new paired seeds1101..1105, 1200 AdamW steps each,
batch128, lr.002, weight_decay1e-4. RNG draws and step counts paired, but input
curricula deliberately differ. Primary numerical binder has no supplied owner ID
in its forward inputs. Learned proposals and guarded success are scored separately.
One development fit seed1191, 1200steps. Infrastructure interruption of pair5
ordinary preparation was restarted from the same parent/seed/recipe; retained log
last reports step800, unknown additional unlogged steps. No excluded seed.

Five rule-based richer-cue calibrations: 4096 unique labelled calibration episodes
per pair, shared by all four feature arms; 16384 feature evaluations per pair.
No added neural matcher: pilot already identified concrete storage/read-interface
separation; rule control suffices to isolate the information effect.

## Pilot decisions (not hidden main tests)
16-stream clean Stage A on parent1: exact ownership preserves the relationship map
but does not resolve frozen-reader near-identity confusion. Resolved identity
owner store selected for the recovery/control track, not accepted as learned binding.
16-stream Stage B: internal key rehydration + nearest value recovery can avoid
32-tick sticky-rejection failures; wrong valid values and erased contents still fail.
No more thresholds or candidate architectures were searched.

## Stage A primary matrix
5 inherited pairs × 6 families × 11 variants × 64 episodes.
Families: ordinary; source-near(.01); source-near(.10); room-near(.01);
intermediate-near(.01); source+intermediate-near(.01).
Variants: exact-owner, inherited, ordinary-trained, near-trained, guarded-inherited,
guarded-near, reject-all in resolved diagnostic; observed A exact-owner, observed B
exact-owner, observed B inherited, observed B near-trained.
Explicit handles enter only the named resolved/checked-commit interface; the
numerical binders receive canonical source vectors, keys and presence, not true rows.
Observed track uses the resolver's index, never substituted with scorer identity.

Phases: initial; registration-only; denied write; wrong-scope write; valid new write;
correction; clear; rewrite; reset; fresh scope. Query old/new/unaffected, separately
score the entire stored relation map and pre/post ownership. Freeze readers throughout.
Physical allocations and registry numbering vary. All 16 codebook rows are allocated
but inactive row is zero: no future identity is in the model before registration.

## Stage B and state/depth regression
Use exact owner installation as an explicitly information-rich infrastructure
control. Parent readers/binders/repairers/head/calibration immutable. 61 scenarios
per pair (the executable list in nbr009/stage_b.py is authoritative and locked).
Shared A/B policy; exact-owner key rehydration plus nearest value repair;
key-only/value-only ablations; unconditional nearest; no repair.
Values never have an undamaged destination ID or graph available to repair.
Nominal noise std .02 each tick; clean/64/1024ticks, cadences1/8/32/read-time.
Four/eight-hop state-on/off cases; depths1/2/4/8 scored from each eight-step trace.
Key/value/both isolation, external q20, common noise, wrong valid destination,
erasure, stale/valid-wrong owner and wrong scope are retained faults.
Invalid-state flags are not successful missing-information answers.

## Conditional cue diagnostic
1024 episodes/family/pair ×12 families, paired evidence for 16D, duplicate32D,
independent2×16D and single32D rule matchers. Secondary informative cue is independent
and mildly noisy in designated conditions (explicit information advantage). Test
missing/conflicting/shuffled/shared-noise cues, novel close in one versus both views,
and identical-observable differing-origin cases. No 32D code is fed into the old 17D
reader. Not a learned semantic encoder or an end-to-end solved recognition claim.

## Screens fixed before main
Exact ownership: zero observed cross-owner commits and unrelated state changes on
denied events; otherwise no engineering adoption. Learned binding: >=95% valid
write/correction/clear success per pair, <=1% wrong-owner proposals/commits separately.
Joint task: >=95% each old/new/unaffected group at enough depth in all core clean
families including near-duplicates. Rejecting valid events fails coverage. Report
at most1pp regressions against paired ordinary/nominal controls. Ordinary novel
acceptance target <=1% empirical; retained parent thresholds unchanged. Richer-cue
results are a separate diagnostic, not a replacement pass on single-vector inputs.
Main learned writer must satisfy both storage and frozen-reader screens; simple
bookkeeping wins do not count as learned recognition.
