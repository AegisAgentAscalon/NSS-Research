## What closes the previous gap
The learner still ends in an immutable review-only proposal. A separate closed
CandidateEvidence001 adapter reads the exact learning cycle, training/evaluation
receipts, snapshot, current archive rights and accepted parent evidence. Its source
format is not the legacy NeuralProbe format and new A2 is never relabeled as old A.

The existing Qualifications owner can now issue narrowly scoped candidate certificates;
the existing Generations owner then requires a distinct whole-family review and new,
expiring source/target-specific release grant. No evaluator score, training approval,
replay grant, old certificate or historical publication becomes deployment authority.
There is no new database, competing current-generation owner or dynamic plugin loader.

## Connected execution actually observed
The current demo reuses the complete task/context -> experience -> reviewed source ->
snapshot -> bounded new-A2 training pipeline. Scripted declared operators represent
human-assisted decisions; no learned router, evaluator or autonomous reviewer is claimed.

1. It trains one new A2 candidate through the approved fixed recipe. The Core and
   accepted A/B stay frozen; the original proposal and parent report are unchanged.
2. It separately qualifies exactly CORE, A2, A2B, A2B -> A2 and A2 -> CORE. Parent
   Core acceptance remains a separate prerequisite, not a substitute certificate.
3. It stages the complete candidate family while the parent remains current. An
   open registered parent stage blocks publication with RECOVERY_REQUIRED.
4. After closing that work, a fresh release grant permits atomic adoption: current
   epoch 1 -> 2, parent archived, target/current/archive/receipt mutually consistent.
5. The managed A2B -> A2 -> CORE task reads actual staged weight bytes. Old tickets
   and old neural state are rejected; target reconstruction agrees with clean execution.
6. After task completion/closure, a separately approved rollback returns the exact
   parent artifact family at a NEW epoch (3). Reading old adoption history does not
   re-adopt the candidate or reopen work.
7. Withdrawing a candidate prerequisite blocks dependent current use. Withdrawing
   its training source permission blocks current candidate evidence. Historical
   records remain inspectable; the restored parent Core-only path remains usable.
8. The previously committed mock external action remains at **one execution**.

The numerical model/recipe is unchanged: a 512-parameter linear identity Core with
small overlays, known individual symbols and held-out pairs. The new checker pins
candidate-specific accuracy/retention/gain criteria and exact saved-metric replay,
not the old AB ablation-superiority claim. The matched joint adapter also succeeds.
No modular accuracy, energy, memory or real-world intelligence advantage is established.

## Failure and authority audit
Current evidence checks bind exact owner receipts, hashes, source revisions, numerical
policy/environment, parent acceptance and named profile/transition. Review separation
checks the ACTUAL training producer as well as the request submitter. Current parent
and local prerequisite checks occur before expensive numerical verification and again
before publication. Review can reject/abstain without being forced to run invalid work.

A truly undertrained, sealed candidate is evaluated and refused; a stored PASS is not
blindly trusted. Wrong formats, aliases, unknown profiles, reverse edges, substituted
receipts, changed code/metrics, revoked data or qualifications, stale epochs, bad grants,
corrupt staging, unfinished tasks and stale state all have explicit refusal paths.

Thirteen new real child-process-exit scenarios cover eleven distinct commit/verification
boundaries, plus expiry/revocation on staged restart. Existing stage, learner and journal
crash regressions remain in the full suite. Completed retries return history, never
another training budget, neural execution permission or publication. Qualifications and
release use public source owners; point-in-time checks do not claim distributed leases.

## Defects/assumptions corrected during this pass
- The first demo TaskRecord draft used `results` instead of `checked_results` and retained
  a previous record's parent pointer. Fixed the new demo to obey the existing schema;
  no validator was weakened.
- An initial generalized claim parser would have accepted A2 through the legacy default
  entrypoint. Kept that entrypoint strict; candidate parsing now needs its explicit
  source format. The inherited unknown-profile regression remains unchanged.
- Candidate lineage exposes the actual learner producer, closing a potential declared
  submitter-name bypass of self-review separation. An added regression exercises it.
- Acceptance checks live parent eligibility before numerical work and again before
  commit. Post-verification withdrawal and staged restart cases are tested.
- Factored neural reconstruction stays inside the existing deterministic CPU policy;
  candidate/legacy state and metrics are not mixed or tolerance-relaxed.
- Generated qualification flow now distinguishes recording rejection/abstention from
  the current-evidence and numerical gates required for ACCEPT.
- Stale active handoff/source descriptions were corrected. The original proposal-only
  demo remains valid; it deliberately does not gain release authority.

## Final scope and next work
This completes the stated connected, trusted-local, single-worker Alpha learning-and-
adoption demonstration. It is ready for independent reproduction and review, NOT a
blanket audit PASS for the entire intended NSS. Local actor labels are not authenticated
people; SQLite/hash checks do not resist a malicious host replacing all evidence.
Neural state recovery is bounded ephemeral activation reconstruction, not serving KV,
device-cache migration, cross-process GPU publication or arbitrary action exactly-once.

The next software campaign is the separately reviewed Runtime clone integration through
an explicit adapter plan. Learned routing/evaluation, realistic nonlinear/generalist
models, larger training, native packed ternary performance, identity continuity, HSA/MSA,
recurrence, DARP, multimodal generation and Core successors remain separately testable
work. No additional demo subsystem is being invented to defer this finish line.
