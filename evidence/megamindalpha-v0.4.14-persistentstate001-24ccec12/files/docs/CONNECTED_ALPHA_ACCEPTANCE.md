# Connected Alpha acceptance — v0.4.13 exact finish line

## Demonstrated local workflow
`candidateacceptance001` reuses the full existing task/context -> experience -> review
-> fixed dataset -> one bounded new-A2 training attempt. It does not copy or fake those
owner results. It then adds five separate exact claims under CandidateEvidence001,
whole-family review, new release approval, durable staging, atomic adoption, execution
of the staged new family, Core-only return and an independently approved rollback.

The source remains current until publication; registered open work blocks adoption.
After publication the parent is archived and old tickets are invalid. The task runs
A2B -> A2 -> CORE through the existing controller, preserves its record, rejects stale
neural-state identity and compares a fresh target computation. Both slots read the
manager's actual staged bytes. The task closes before rollback. Parent artifact identity
returns at a NEW epoch; old publish retries cannot re-adopt the candidate. The single
prior mock effect is not repeated.

After success, the demo withdraws an accepted candidate prerequisite and new training-
data source permission. Dependent current use is blocked. History remains available.
The parent lineage is separate and its Core-only path still works after rollback.
The learner's original review-only proposal and parent neural report remain unchanged.

## How to reproduce and inspect
```console
python -m nss_base.candidateacceptance001 --directory ../candidate-demo
python tools/verify_connected_alpha.py --summary ../candidate-demo/summary.json
```
The second command validates recorded history against actual public owner records,
exact candidate receipts, certificates and adoption/rollback transactions. It does not
perform new numerical work, issue permission or ignore the demo's final revocations.
The earlier proposal-only demo/verifier remains valid and does not gain release power.

## Conditions that must stop progression
Wrong evidence format/name/hash/receipt; missing or revoked parent or local prerequisite;
actual trainer as reviewer; failed frozen metrics; wrong/expired/revoked release grant;
open stage; corrupt staging; stale source epoch; uncertain prior action; numerical
rebuild mismatch. Completed history never overrides these conditions for new use.

## What complete means here
The six planned software areas plus one new-candidate acceptance integration form a
bounded human-assisted local Alpha demo. No more major demo subsystem is required to
claim this particular loop. An independent review may still find defects to repair.

It is not the full NSS, an authenticated authority, autonomous learner, protected
benchmark, general-purpose model, native GPU/ternary serving runtime or a production
release. The existing candidate is a 128-parameter linear overlay around a 512-parameter
identity Core. All single symbols are known during training; pair combinations are
held out. The joint baseline also succeeds. No new accuracy or energy superiority is
claimed by adding the acceptance software.

Neural recovery covers explicitly tested fixture inputs and ephemeral activations.
Native serving/cache/device rollback and a larger nonlinear task require their own
contracts/evidence. Integration with the separately reviewed Aegis Runtime NSS clone
is the next software campaign, not something hidden inside this finish-line label.
