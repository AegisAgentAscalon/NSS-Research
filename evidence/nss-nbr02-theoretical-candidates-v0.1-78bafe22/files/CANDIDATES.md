## Proposed DC01 v0.2 contract for Chat to freeze

**Task and information.** Two software-routed scopes share a small online predictor. A public cue/action event precedes one legally identified feedback receipt by 0, 8 or 32 intervening filler events. Only one scored receipt is pending at a time. Its ID names the earlier event but does not replay cue features or reveal future answers. A stream contains several associations; a declared subset reverses one mapping without advance notice while unrelated mappings remain stable. Query probes are read-only and scored before any receipt update. This isolates retention of *unrelated* old associations from correctly replacing a reversed mapping. Public exact history may be retained at a cost; hidden outcome labels and scorer-only no-cue flags never enter a learner or gate. Freeze event grammar, scope checks, feedback validity, malformed/shuffled receipt behavior and causally available features before generation.

**Fixed model and reset.** Propose a 16-unit tanh recurrent encoder `h_t=tanh(Wx_t+Uh_(t-1)+b)` and two-class softmax readout `p_t=softmax(Vh_t+a)`, with fixed input vocabulary, trainable surfaces `W,U,b,V,a`, one recurrent step per admitted event and no variable internal depth. Freeze at least three causal context/input events ending at the cue and require nonzero off-diagonal `U`, so the recurrent-gradient approximation is exercised. Both arms get identical event vectors and an ID-only pending queue. Clone **weights/learning state only at condition-stream start**. Trials within that stream retain adapted weights; each trial starts with zero recurrent state and cleared eligibility/pending receipt. Between cue and receipt, weights are frozen; filler forwards may change live `h` but not the stored cue-time graph/trace or prediction. At receipt, score the earlier prediction, apply at most one update, then clear pending cue, recurrent state and eligibility before the next trial. Read-only probes must not mutate weights, optimizer, eligibility or live state. Thus filler-altered live state cannot affect the next cue, while parameter learning persists. State carry or overlapping feedback needs a separate version.

**G, exact gradient.** Retain the *upstream* computational graph that produced the cue-time prediction under a single parameter version. On receipt, compute cross-entropy against the now-visible label and take one SGD step. The graph may include preceding context events in that trial; it never includes later filler events, which are not causal ancestors of the prediction. Freeze its upstream truncation length, cue-time parameter snapshot rule, precision, learning rate and clipping before evaluation. A fresh adaptive replay must repeat every update, not merely forward final weights.

**L, proposed diagonal eligibility hybrid.** Use the same network and SGD step size. At causal events through the cue, maintain per-neuron approximate recurrent sensitivities. With `d_i,t=1−h_i,t²`, set `eW_i,j,t=d_i,t[x_j,t+U_i,i eW_i,j,t−1]`, `eU_i,j,t=d_i,t[h_j,t−1+U_i,i eU_i,j,t−1]`, and `eb_i,t=d_i,t[1+U_i,i eb_i,t−1]`. At the cue retain these arrays and `h_c,p_c,V`; later fillers do not alter that snapshot. On label `y`, let `q=p_c−one_hot(y)` and `δ=Vᵀq` from the cue-time version. Update `W_i,j←W_i,j−ηδ_i eW_i,j,c`, likewise `U_i,j,b_i`; update `V←V−η q h_cᵀ`, `a←a−ηq`. This is **not** exact recurrent gradient, RFLO or e-prop by name: it drops cross-neuron terms `U_i,k ∂h_k/∂θ` for `k≠i`, while readout uses the ordinary gradient. Before training, a separately implemented derivative check must match G in a diagonal-`U` special case. On a fixed development task witness with nonzero off-diagonal `U`, predeclare a meaningful relative recurrent-gradient discrepancy `||g_G−g_L||₂/max(||g_G||₂,ε)` (candidate ≥0.05, exact norm above a fixed floor); require it before held-out generation so the omitted paths actually matter. Freeze witness, floor, tolerance and verifier cost first; a later learned near-diagonal solution is reported, not a reason to tune the gate. Freeze trace reset, precision, clipping and decay. Report accuracy and trace bytes/operations. If L fails immediate-feedback competence, stop or redesign in a new version, never after held-out results.

**Controls and units.** `N_G` and `N_L` fork the respective arm's **post-initial-fit precondition checkpoint** at condition start and make no online updates: zero extra optimizer attempts, but charged forwards/storage. Compare each learner's online gain against its own frozen fork; an untrained model is optional and separately labeled. X is causal cue→last-observed-feedback bookkeeping, with full history/index bytes, reads, writes and scope checks charged. X can be unresolved before feedback and lag an unannounced reversal; it is not gold. One **development-only** shuffled-receipt stream per arm/seed uses a valid future-free permutation and ≤6 charged updates, outside the 72 paired streams and held-out decision. Each of two development and four held-out template families has two independent bases. Cross each base with delays 0/8/32 and reversal absent/present, changing only timing/schedule. This gives 24 development and 48 held-out condition streams from eight held-out bases, with five read-only **post-receipt/reset, pre-next-update probes** per held-out stream: 240 condition-occasions. This isolates learning comparisons from filler-altered live `h`; during-delay probes would be a separate state test. Freeze train/development/held-out mapping identities so initial/development exposure cannot teach held-out associations, plus disjoint seed namespaces and normalized-overlap checks. All four paired seeds remain in scoring after the group development gate; no successful-seed selection. Compare paired conditions by base/family and report seed variation.

**Staging and outcomes.** First require both learned arms to demonstrate immediate-feedback learning on development only. A candidate per-arm gate is at least 32/40 correct pre-update zero-delay development probes and at least eight more than its own `N_G/N_L` fork in at least three of four seeds, with no illegal update; Chat must freeze task difficulty and this threshold before held-out generation. If G fails, stop and report baseline incompetence. If G passes but L fails, stop the confirmatory delay comparison and report **local-rule baseline deficit**, not a delay effect; do not tune L after seeing held-out data. If both pass, paired 0/8/32 conditions test whether retained cue-time updates and later predictions are invariant under irrelevant filler; differences imply a contract, storage, implementation or state-reset issue to diagnose, not automatically temporal credit. Score **all four seeds**, including any that missed the per-seed gate, on new-association accuracy, unrelated-old retention and illegal updates. A claim of L advantage needs a predeclared accuracy/retention noninferiority margin and lower *total* cost; a smaller trace alone is insufficient. Freeze margins before held-out generation and retain every negative.

**Global budget, verification and stops.** Supersede the earlier provisional 4,900-attempt ceiling because full adaptive reproduction was omitted. Per learned arm/seed allow **600 total attempts**, not 600 per stream: provisionally ≤100 initial + ≤6×72 paired-stream receipts + ≤6 shuffled-development receipts =538, with 62 unused reserve. Four seeds×two arms allow ≤4,800; two 50-attempt cost probes add100. Reserve the same ≤4,900 for one full independent-process adaptive reproduction including probes: **9,800 global optimizer/local-update attempts**, with failed, skipped and in-flight work charged. Scheduled two-pass work is 2×(8×538+100)=8,808 if no attempt fails. Replay is not an independent sample; no counter resets. Meter recurrent forwards, G backward work, L trace updates, derivative-check work, X operations, queue/storage/traffic, checkpoints, evidence and replay separately. Before execution freeze a forward/work cap and static evidence bound from actual shapes, then measure host feasibility; the earlier two-hour, 3 GiB process-tree/3.5 GiB container, 256 MiB raw and 64 MiB ZIP ceilings are provisional limits, not runtime forecasts. Stop for malformed authority, missing causal identity, source drift, nonfinite updates, leakage, failed competence or resource overflow under a frozen rule; poor held-out accuracy is a retained scientific negative. No model, source lock, fixture or actual host cost has been demonstrated by this review.
