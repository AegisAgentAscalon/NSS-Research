# One-pass decision checklist

Return a completed checklist with PASS_AS_PROPOSAL / CORRECTION_REQUIRED / BLOCKED_PENDING_EXECUTION. These labels refer to design readiness, not numerical success. Findings need a concrete counterexample, accounting discrepancy, or unsupported assumption, plus the smallest change required.

1. **Scope:** same inherited model/SGD/receipt/event/scoring contracts; exact-old derivatives and buffer assistance explicitly paid; no hidden extra phase or PAIR01.
2. **Mathematics:** parameter-displacement sign; full-row KKT; zero/rank/near-dependence; no constraint omission; no nonlinear guarantee claimed.
3. **Actual update:** fixed float32 B1/B2 behavior; specified P conversion; independent byte check; both negative applied residuals and rounding bounds retained.
4. **Control:** S uses actual B2 direction and actual P norm; no post-score search; degeneracy, mismatch and equal protection-computation cost explicit.
5. **Public evidence:** all eight targets from lawful receipts; current correction/invalidity handling; baseline-wrong examples retained; no obsolete focal target or privileged scorer data.
6. **Learning and calibration:** B1-only competence/calibration, all fits retained after group admission, fresh mapped confirmation after lock, abstract grammar overlap acknowledged.
7. **Outcomes:** first-flip benefit, B2 focal nonregression, per-tail old-label preservation and confidence guards; P–S remains separately exploratory; raw failures stay raw.
8. **Work:** reconcile each JSON count from the concrete schedule. Check initial/probe/frozen/fixture/reconstruction/margin/solver work, counts for zero or rejected applications, adaptive replay and unknown-completion rules.
9. **Storage and host:** identify implementation-time schema and native-memory evidence still needed. No extrapolated archive-size promise. One bounded resource gate before main fitting.
10. **Final disposition:** identify any documentation blocker still preventing implementation. Runtime fixture/admission tests are normal remaining execution gates; they are not evidence the documentation has already passed a numerical experiment.

Do not simply answer “looks good.” Return patched normative paragraphs/JSON when a correction is needed, and state explicitly whether it changes scientific observations, only the numerical implementation, or only bookkeeping. Do not create a new candidate portfolio or increase study scope without identifying a blocker that requires it.
