# Dream-linked foundational maintenance
## CAND-NSS-DREAM-MAINT-001 / ACP-NSS-DREAM-MAINT-001 — concept v0.1

**User idea:** connect periodic foundational refresh to the Tertiary core's dream mechanic. **Status:** PROPOSED_ARCHITECTURE_LINK, not adopted implementation, verified plasticity recovery, authorized training, or a REV01 arm. This is our interpretation of the user's suggestion, separate from the attached Codex proposal.

## Why this fits the retained role
The architecture ledger A1 already assigns Tertiary prediction, imagination, reflection, consolidation preparation and functional appraisal, while Secondary is inactive and Primary remains a frozen participating core. It assigns parameter-training jobs to Forge and acceptance to the governed qualification path. Thus dreaming need not be an endless language monologue: it can propose meaningful replay, counterfactual tests and maintenance artifacts. This does not make imagined outcomes observations or replace the Tertiary's broader roles with a replay scheduler.

F1 proposes broad foundational rehearsal from the current checkpoint, not a random reset, and distinguishes improved recall from recovered new-task learning. Connecting F1 to dreaming supplies a possible preparation/selection phase, not proof that scheduling the same data at night makes it more effective.

## Proposed end-to-end lifecycle
1. **Safe task handoff.** Secondary finishes its permitted post-task phase; preserve a versioned event cutoff, unfinished work, current constraints, known failures and confidence observations. Resolve pending receipts or apply a separately approved cancel/reconstruction contract. Checkpoint the outgoing auxiliary and pause its activity. Retain rollback and source records.
2. **Primary + Tertiary reflection.** Tertiary examines allowed experience, failed or uncertain transitions, rare skills, verified corrections and rehearsal coverage. It can explore counterfactual branches and propose candidate tests. A declared budget limits compute/retrieval; none is assumed free because the user is asleep.
3. **Evidence-qualified rehearsal plan.** Produce an inspectable dataset manifest: source IDs/revisions, why each item is selected, observation versus simulation status, target provenance, obsolete-fact treatment, exclusions, and claimed skill dependencies. Mixed old/new/foundational coverage is a candidate policy, not a fixed percentage adopted here.
4. **Separate candidate training.** First conservative scheduling option: pause Tertiary once the plan is produced, then run a separately approved Forge candidate-maintenance phase. Do not secretly keep Secondary learning while Tertiary is active. An offline candidate is not automatically an active Secondary, but any concurrency policy needs an explicit architecture decision and cost/behavior tests. No concurrent-write permission is inferred here.
5. **Qualification and resumption.** Evaluate old/current skills, false reversion to obsolete facts, genuinely fresh post-maintenance learning, and composition with the accepted Primary. Validator advice is fallible evidence, not a release permit. The authorized process adopts a complete compatible candidate or rejects it; no candidate self-approval. Resume with a versioned state migration/replay/reset policy. Primary changes require a qualified NEW generation, not in-place mutation of the current Primary.

This is a two-timescale proposal: ordinary online learning plus costed, deliberate consolidation. The current experiment does not implement a Tertiary, this pipeline, or integrated NSS operation.

## Three products of a dream must remain different
- **Experience replay:** re-use an actual record, respecting its original context and any later correction. The archived event remains what was observed/reported, not necessarily objective truth.
- **Verified synthetic exercise:** a counterfactual with a target supplied by an independent lawful simulator, exact rule or external check. Preserve the generator/verifier version and assumption scope. Verification of toy arithmetic is not evidence that a real-world prediction is true.
- **Unverified hypothesis:** a possible explanation or imagined outcome. Store as hypothetical with a proposed test. Do not train it as an established factual target merely because Tertiary or Primary is confident or repeats it.

A changed historical setting must not be rehearsed as today's setting. Failed attempts should teach applicable operations or contextual distinctions, not simply repeat obsolete answers. The maintenance selector itself cannot see withheld future plasticity-test tasks or their labels.

## Maintained management workspace as a phase organizer
A bounded packet could identify phase, selected source cutoff, active investigation, candidate-job reference, unresolved tests and permitted output TYPE. The archive holds the evidence; the larger Working Space holds plans and artifacts; latent processing holds exploration. Token fields do not themselves confer training permission. This is not a proposed fixed vocabulary, field count or native embedding size. Reuse slots; separate residency, consultation and rewrite cadence.

## What benefit would need to be demonstrated?
First show whether balanced rehearsal helps relative to no refresh and equal-budget recent-only refresh (F1). Then test any claimed Tertiary-selection contribution against a strong rule-based/balanced selector with the same available experience and metered selection+training resources. A fixed source-copying selector would establish software rehearsal, not learned dream intelligence.

To isolate timing, compare the SAME selected records/update budget in a maintenance block versus distributed replay; to isolate imaginative synthesis, compare validated synthetic additions against an equal-cost non-synthetic control. Do not change timing, data, capacity, optimizer and rejuvenation simultaneously and attribute the gain to dreaming.

Old-skill recovery is not restored plasticity. New-task learning must be measured after maintenance on withheld tasks, from clean matched task state, with matched difficulty and a competence-learning curve. A recovery claim requires a documented pre-maintenance deficit. If the unmaintained control never loses plasticity, a post-maintenance success is not evidence of repair. A refreshed model that remembers older answers but undoes recent valid corrections fails the current-knowledge constraint.

## Failure-first record requirements
Record selection rationale versus actual source support, every dream/verified/observed origin, dataset versions, parent/candidate parameter IDs, optimizer and RNG lineage, pending-trace dependencies, interruption point, partial commits, retained state compatibility, raw skill changes and all rejected candidates. A generated exercise that breaks its target verifier stays a failed synthetic candidate. Do not replace it with an easier sample after observing a score. Promotion of a hypothetical label into the observation lane is a protocol failure.

Interrupted dreaming is resumable proposed work, not a completed discovery. Interrupted candidate training does not mutate the accepted serving checkpoint. A rollover without compatible recurrent-state handling remains an open integration failure even if offline accuracy rises.

## Roadmap and open choices
Link F1, RET-MW01-FIT-001 and FCR-0103-001. This is a potential foundation-consolidation/maintenance experiment, not a new mandatory gate on completed NBR-01 or a reason to delay REV01. Open: selector, target provider, rehearsal mixture, schedule/trigger, which adaptive surface changes, latent/cursor handoff, promotion criteria and actual local hardware costs. Retention and plasticity are core research objectives; dream-linked rehearsal is one candidate way to support them.
