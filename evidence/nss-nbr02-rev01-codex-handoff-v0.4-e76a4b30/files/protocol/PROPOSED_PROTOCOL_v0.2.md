## 1. Question, model and treatment
Does permitting a larger single correction at an observed label change improve the immediate new-label answer without harming unrelated old knowledge? Treat G and L as separate methods; do not pool them into a chosen winner. Replicate the DC01 674-parameter float32 tanh network H16,D23, two logits, three causal events START/PRIME/CUE, and paired initialization. Inherited array order W,U,b,V,a. G differentiates exactly through those events. L uses the pinned diagonal-sensitivity recurrence, omitting cross-neuron propagation. L is approximate, not a new nongradient law. Source equations and routines are identified in SOURCE_IDENTITIES.json; every borrowed scientific routine must have an execution-time identity or a justified pre-generation amendment.

For raw concatenated gradient g, use factor s(c)=1 when norm(g)=0, otherwise min(1,c/norm(g)), then theta_next=theta−s(c)g. Learning rate1, no momentum, weight decay, projection or rescaling besides this global clip. Use inherited operation/dtype order, including float32 update and declared norm computation. All initial/probe/prefix/tail updates use c=1. **Only the first validated changed-label receipt uses c=1 in B1 versus c=2 in B2.** Record actual factors and step sizes. Norm<1 produces no treatment difference;1<norm<2 produces less than a twofold step; norm>=2 permits a factor-of-two step. Do not remove any such stratum.

## 2. Public change detector and fork boundary
Each arm maintains a paid last-observed table keyed by(scope,cue identity), with(label,receipt/event reference,version). The association key comes from the legitimate pending cue, not feedback features. The receipt contains scoped ID, parameter version and outcome, not the cue vector. A new cue without a prior public label is not a label change. An invalid/mismatched/consumed receipt changes neither parameters nor table.

Validate receipt → compare outcome with the PRE-receipt table → if it is the first disagreement in the condition, durably record the fork → apply both branches from the common cue-time parameter version → commit their table updates. The control receives the same detector and bookkeeping. An internal per-condition “used” flag prevents a second boost. No hidden reversal indicator, trial index, future target or scorer ledger reaches this detector.

The planned streams put a disagreement at trial3, but that is a generator/scorer fact only. State-machine tests must also cover an earlier/later change, first-seen receipt, repeated label, duplicate/foreign ID and unidentifiable authenticated wrong label. These non-neural tests are not extra training streams.

Before either application, freeze the common parameters, public prefix, previous table entry, pending state and prediction. B1 retains the real pending G graph or L trace. B2 is a distinct copied parameter instance and reconstructs the identical three-event prediction/trace in the same runtime; it must match hidden states, logits and raw gradient bitwise. It does NOT replay the earlier learning prefix or refill the detector from hidden answers. Rebuilding B2's causal cue is included in its counted update exposure. Detached waiting state, if present in a fixture, is copied as an inert recorded value, not replayed as gradient ancestry. The target is already lawfully released at this point. Reconstruct the forward state without target-dependent inputs and verify it against the original pre-feedback prediction; only then use the released target to calculate each raw gradient. The reconstruction is marked RECONSTRUCTED_AT_FORK, not timestamped as a new prediction made before feedback.

Each branch then has its own mutable weights, trace/graph lifecycle, table, cursor and audit lineage. Shared immutable snapshots are allowed only with explicit storage ownership and mutation checks. Queries cannot refresh state or modify the table. No “deep-copy the Python autograd graph” portability assumption. If exact branch reconstruction is unavailable, stop before fitting or revise the proposal.

**Development-informed confidence tolerances, formula fixed now:** for each method separately, take all4 development bases×4 fits at post-trial3 and4. Define m_loss and m_margin as the ordinary midpoint median over the32 values for each metric. Set tau_loss=min(0.01,max(0.002,m_loss)) nats; tau_margin=min(0.02,max(0.005,m_margin)). This calibration is a declared pragmatic tolerance, not a confidence interval or established acceptable deployment harm. Its upper caps prevent a bad baseline from authorizing unlimited confidence damage.

## 6. Held-out decisions, G and L separately
Eight bases×four fits give32 repeated paired measurements per method, not32 independent association families. The interpretation unit is the paired base; show the entire base×fit grid and both reversal directions.

**Efficacy:** B2 must yield at least one net extra first-correction class success in>=3/4 fits; positive net class gain averaged over fits in>=6/8 bases; and pooled first-correction log loss no worse than B1. Publish wins AND reversions. These are the source proposal's exploratory requirements, not a statistical superiority test. An already-perfect B1 can make improvement impossible; retain that ceiling/null result rather than lower the bar or select only B1 misses. A fixed numerical reporting tolerance1e−12 may resolve floating comparisons, never hide a substantive loss.

**Old-label retention:** at every tail checkpoint3,4,5,6, B2 must preserve every old label that was correct at the common pre-fork checkpoint AND introduce no additional wrong label relative to B1 at that same checkpoint. Record baseline old errors separately. No wrong-scope/duplicate/unauthorized application may occur.

**Old-confidence retention:** at each tail checkpoint and in each base (averaging4 fits and8 old cues), require mean loss(B2)−loss(B1)<=tau_loss and mean probability-margin(B1)−margin(B2)<=tau_margin. Require the same pooled constraints and report every individual cue/fit departure and extrema. Paired means cannot erase any class loss. Include final inventories, immediate old-confidence trough and conditional focal/old tradeoffs.

**Interpretation:** efficacy plus all retention/engineering guards supports a bounded method-specific one-step-dose result. More first flips with confidence/label damage is a tradeoff, not a pass. No effect when the new gradients are unclipped is still a valid outcome. G/L may differ; do not select the favorable method after results. This does not prove clipping was the unique original cause, broad reliability to corrupted feedback, plasticity restoration or an overall resource advantage. DC01's accepted screens remain unchanged.
