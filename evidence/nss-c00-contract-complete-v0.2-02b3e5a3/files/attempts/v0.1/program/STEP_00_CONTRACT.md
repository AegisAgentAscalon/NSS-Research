# Contribution 00 — the first contract
## START-NSS-CONTRACT-001 · initial specification, not an executed test

**What starts now:** define the promise, the evidence and the decision objects. This is not starting NBR-01 over, rerunning past experiments, or lifting the experimental hold.

## A. Proposed promise

> A useful correction must become available within a declared bounded delay. The permitted old-capability impact must be explicit, monitored against a stable reference, and repaired within an agreed work/latency bound when repair is required. Neither permanent rejection nor unbounded repair counts as success.

The target is retained useful behavior plus continuing adaptability, not immutable weights or perfectly unchanged probabilities. The paper-inspired generator is a later contribution; it is not required to define whether an update is acceptable.

## B. Initial primary question

**Before changing learning or rehearsal again, can an evidence-grounded review accurately distinguish acceptable, unacceptable and unresolved candidate changes, without suppressing valid corrections?**

This is a proposed review/adoption question. The first minimal comparison should hold candidate work and permitted observations fixed. It does not claim better intrinsic learning or plasticity. Results obtained by withholding a candidate must be reported separately from its raw learning outcome.

A minimal software-level rule and ledger come before a learned reviewer. This is an engineering prerequisite, not another purportedly novel neural architecture. Do not implement or execute it until the remaining protocol choices are fixed and the user explicitly dispatches that study.

## D. Proposed change-record contract

One record links, without duplicating the entire archive into tokens:

1. Change ID, domain, task/scope, parent state/parameter/codec version and candidate identity.
2. Intended correction and its observed evidence; source revision and released-feedback cutoff.
3. Current protected capability set, rolling parent and stable qualification epoch.
4. Before/after evidence references, measurement boundary, update attempt/completion and gaps.
5. Review status, supporting checks, uncertainty, affected obligations and review depth.
6. Accept/defer/reject decision, actual serving identity, repair/adoption deadline and work consumed.
7. Since-last-dream interval, unresolved older links and accounted-through cursor.

This is a semantic schema draft, not a selected on-disk format or token string. Extensive measurements, tensor snapshots and history remain in the exact archive. The small workspace carries references and current management state. A record saying “verified” without a check is not verification.

## E. Design examples to settle meaning — not scored cases

| Situation | Intended classification |
|---|---|
| Authoritative evidence changes a focal target; the candidate learns it and remains within the agreed old/new envelope. | Potentially acceptable adaptation, not forgetting merely because the old focal answer changed. |
| Focal target learned, some old probability margins decline within agreed limits, labels remain usable, no accumulating/deadline breach. | Potentially acceptable bounded disruption. This cannot be decided until those limits are defined. |
| Focal target learned, a required old capability crosses an unacceptable boundary. | Defer for bounded repair or reject under policy; do not average it away with unrelated gains. |
| Excellent old behavior because every correction is rejected. | Fails the useful-adaptation/availability requirement. |
| Reference is current, but evidence-dependent unfinished work was not recomputed. | State/evidence issue; correct metadata does not establish correct work. Requires the separate state-domain check. |
| Hypothetical dream exercise is written into the record as an observed user fact. | Integrity/provenance violation, not a tolerable confidence cost. |
| Update intent exists but no durable completion; candidate version cannot be established. | Unknown completion/incomplete evidence; no invented pass or free retry. |
| A dream interval is fully enumerated, but some changes require more evidence. | Accounted for with unresolved obligations, not fully repaired. |

## F. Limits that must be chosen before execution

**Hard integrity:** source authority, permission, known parameter/state version, causal feedback boundaries and honest completion accounting are not traded for accuracy.

**Behavioral allowance:** old classifications/probability quality, severity tiers and cumulative deviations need numerical values tied to the selected toy or application. The old B1-relative confidence values are historical; they are not operationally calibrated safety levels.

**Useful adaptation:** specify minimum new-task behavior and a maximum delay in receipts, applications or time. A correction held indefinitely cannot qualify.

**Bounded maintenance:** specify one finite allowed cycle and its end condition. No unlimited “repair until pass.” Whether a tolerable change may be served with an outstanding repair obligation requires explicit policy; provisional status alone is not permission.

**Evidence panels:** define public guard/rehearsal records versus independent confirmation, current-label versioning, identifiable review outcomes and unknown cases. A complete eight-item check proves nothing about unobserved skills.

**Statistics and costs:** choose the actual units, simple attainable criteria, fixed data construction, independent source/scorer separation, full call/update/replay/native-storage accounting and a fresh run budget.

These are remaining design choices. This sheet does not invent values to make old results pass. The next deliverable is one numerical/engineering protocol, not automatic execution of all contributions.
