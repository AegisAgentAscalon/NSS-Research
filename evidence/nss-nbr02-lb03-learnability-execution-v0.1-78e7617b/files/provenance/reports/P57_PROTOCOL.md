# NSS LB02-Q2-TRAIN v0.1 — prospective bounded comparison

## Question / ELI5
Can our established checklist learner retain old work, learn a corrected cue, and use less persistent learning memory when its matrix weights have four allowed levels? Does compressing Adam's running notes earn its cost? Ternary is the long-term direction; Q2 is an interim candidate. No BitNet model is fitted, and two-bit serving weights do not imply two-bit arithmetic or training.

## Scope and arms
Four exact original SURFACE01 parents 4101–4104 copied as arrays from verified LB01-TERNARY inputs. GRUCell(26,64)+Linear(64,9),18,249 coefficients; all trainable. Three branches per parent:
- F32_M32: float32 forward matrices and FP32 moment arrays.
- Q2_M32: row-affine four-level quantized forward matrices, FP32 master coefficients/gradients and moments.
- Q2_M8: identical quantization and preparation, compressed 8-bit moments plus FP32 block scales.
No old post-QAT checkpoint, teacher, adapter, label-based inference guard, new model fit, language model, HSA, DARP or other research component is introduced. All endpoints retained, no seed/arm selection.

## Numerical representations
Q2 row scale is max((max(w,0)-min(w,0))/3,1e-8), min/max include zero. Zero point is round-to-even(-min/scale), clipped0..3. Codes=clip(round(w/scale)+zero,0,3). Forward value=(code-zero)*scale, FP32-rounded. Four codes per byte at serving; FP32 scales and biases and uint8 zero points cost extra. Scale/rounding derivatives stopped; backward identity straight-through surrogate explicitly not true quantizer derivative.
SQ8 custom Adam stores signed linear first moments and unsigned square-root second moments, in independent blocks of at most128 scalars. First scale=max|m|/127; second scale=sqrt(max(v))/255. C code updates from decoded previous moments, uses the unquantized updated moments for this parameter step, then repacks them for the next step. This is a custom inspired comparison, not bitsandbytes/Dettmers code or full reproduction. Both optimizer backends use the same C float-state/double-local equations and one128-element m/v scratch pair (1,024 bytes); neither retains a full decoded M8 array. Wider FP32 master/gradient, floating effective matrices/activations remain. Adam scalar counter stored as Python int, not a model-sized array.
Training forward/backward is FP32; evaluation independently checks FP64 arithmetic applied to exact effective FP32 coefficients against PyTorch GRU and NumPy equations. Q2 direct C kernel reads packed codes, uses FP64 state, and is checked against decoded reference. No native integer training or optimized SIMD speed claim.

## Learning schedule
All arms receive the same64 archived A batches per parent, repeated16times (1,024 updates), paired with all8 original B cue labels. Fresh Adam, lr.003 cosine to.0003, betas .9/.999, epsilon1e-8, no decay, global clip1.
Then fresh Adam:64B-only updates lr.003 to flip cue0 from0to1; the other7 remain current. Then fresh Adam:32A+current-B replay steps lr.003. First32 original replay batches in identical order for all arms. This deliberately replaces LB01's jointly trained acquisition phase that failed even in float. It borrows CYCLE's B64+AB32 structure but uses these FP32 masters/optimizer, so successful acquisition is tested, not inherited.
Maximum 12branches×1,120=13,440 main optimizer applications. Preflight maximum64 applications inclusive of failed diagnostic work. Fixed checkpoints0,256,512,1024,1088,1120; intermediate development curves are not used to select endpoints. No extra training after confirmation. No automatic adoption/live serving; all learned candidates evaluated.

## Endpoint interpretation
Preparation working point: Aevent>=98%, whole>=90%, event loss<=1pp from own unchanged float parent, zero new falseDONE at formerly correct completion positions; all8 original B classes with min target probability>=.8. Learning endpoint: same A rule plus all8 current B classes/minprob>=.8. At least3/4parents needed for a provisional cohort working point. Probability is not calibrated confidence.
Compression adequacy requires Q2_M8 not lose more than1pp event or2pp whole vs paired Q2_M32 and no extra falseDONE; both need underlying working quality. Persistent master+gradient+moment payload reduction >=25% is a separate resource criterion, not total-process proof. Event improvements cannot replace whole-task qualification. Record positive learning even when strict criteria fail. If float acquisition fails, report shared-recipe limitation and do not blame precision alone.
