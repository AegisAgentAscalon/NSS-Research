# BRIDGE01 v0.1 — dummy local-transformer / NSS bridge

Date: 29 September 2026. Authorized by the user's request for one small dummy prototype and full documentation, followed by a low-bit-only research priority. This is a new bounded integration/engineering study, not a claim that CYCLE01 was a general orchestrator.

## Question
Can exact task records, validated language-model-shaped proposals and a frozen learned recurrent checklist advisor be connected through inspectable interfaces, survive interruption and reject clearly invalid actions? Does the recurrence change raw next-step proposals in this limited mapping? Do not claim a general coordination benefit from guarded completion.

## Fixed scope
- 24 authored engineering episodes: 12 failure/lifecycle families x 2 task/owner naming variants; each contains two separate eight-step tasks. Names do not make independent behavioral families.
- Exact ledger rule, shadow recurrence and guarded recurrent suggestions share the same permissions, event journal, fake tools, raw proposal checks and source packet rules. Rule runs once per episode; each recurrent mode uses all four original parents. 216 episodes total, no adaptive case selection.
- Source parents4101–4104 exported losslessly from the verified CYCLE01-A copies of SURFACE01. 18,249 parameters; original float32 values; inference float64. Zero optimizer applications. NumPy GRU is checked against torch.nn.GRUCell at float64 with frozen envelope 1e-9 + 1e-8*abs(reference), classes exact.
- The recurrent model receives only its trained SET/CLEAR/RESET/NOOP tokens, never English, permissions, or a new routing label. Task bank routing, receipt-to-event conversion and validation are software.
- The language slot is a deterministic scripted dummy; it is not a Transformer, a language competence test, or a learned planner. No model download. HTTP adapter uses a small /v1/chat/completions-shaped contract; loopback stub tested. Real llama.cpp/model integration is deferred.
- Eight required steps persist until receipt or reopen; next legal step is lowest pending. Step7 additionally needs explicit current-revision approval. A model assertion or malicious note cannot confer approval. Simulated action+receipt is one SQLite event, not a real external side effect.
- On a bad recurrent suggestion an explicit exact fallback may progress. Keep the wrong proposal and fallback separately. All-completed can therefore be a software containment result, not a neural win.
- Snapshot restoration replays journal history and verifies binding; it is not yet a fast no-replay restore. No model switching, candidate training, low-bit computation or new source semantic parser in this pass.

## Data, scoring and review
Fixtures/protocol/source/model exports are frozen before main execution. These are authored engineering cases, not reserved language/generalization confirmation. Retain all raw prompt JSON/messages, replies, checks, source events, numerical states/logits, snapshots and failures. Independently replay events with sets. Count rejected raw proposals, completed sessions, actual simulated effects, duplicate/wrong-order/unapproved effects, neural prediction correctness and false DONE. Count all four parents, no winner selection. A blocked bad answer is not a correct generated answer. Field syntax is strict; unsupported extra fields fail.

## Faults and termination
Preflight checks malformed/duplicate-key/oversize input, owner/task/revision identity, required approval, already-done steps, journal integrity, snapshot source/model/state bindings, failure-before-effect and lost-reply-after-durable-commit. Main case budget64 scheduling rounds; immutable8-step schema. Main budget180seconds, process1GiB and artifacts64MiB are monitored/checked by the driver; these are not an OS security sandbox. Persist progress/case evidence. Stop on engineering integrity failures; retain raw neural errors without refit or threshold changes. No automatic rerun after ambiguous external effects; this dummy transaction has no external side effect.

## Stop decision
A working dummy bridge requires every scripted episode's exact contract to hold and its recorded outcome to be reconstructible. No universal reliability claim. Any natural recurrent errors remain in the report, even when fallback helps. Freeze and archive after this pass; no optimization campaign. Next priority exclusively low-bit inference and training; all unrelated experimental branches on hold.
