# Development record — before main registration

All development used the separate HorizonBinding002 representation141, not
main representations301–305. No main outcome was inspected to tune the model.

1. Two 900-step random-initialized recurrent preparations (seed441), balanced
   empty examples plus 1/2/4/8/16-round noisy teaching, with/without an empty
   directional contraction loss. Empty behavior improved, but established
   values failed long maintenance. These runs are retained and not main evidence.
2. Two 1,800-step continuations (seed442) of the old 600-step development repair,
   with a shared exact-code fixed-point anchor loss. Clean known/empty/write
   behavior passed. At 0.15 chronic noise, empty accuracy was100% but the sampled
   address's known accuracy was78.125% /76.5625%. This is a joint-quality warning,
   not a successful robust memory. This recipe is retained for the paired main
   replay/contract comparison with the actual competent main parents.
3. Two 1,800-step continuations (seed443) added known-neighborhood ratio losses.
   At0.15 noise, sampled known accuracy fell to37.5% /14.0625%. This recipe was
   NOT selected. The old train implementation and every checkpoint/log remain.
4. One900-step development fit (seed444) kept the parent's network frozen and
   fitted a one-scalar continuous local empty-region gain. It also failed the
   developmental long-known screen. It remains a separately declared structural
   challenger in the main comparison; no success is presumed. A small gain
   change can affect existing attractors. Its exact EMPTY=0 convention and
   reliance on this code scale must be disclosed.

teaching, exact write/clear events and exact-code anchor rehearsal. The local
candidate receives the same data but adapts only one radius and retains the
parent network. It is NOT a matched-trainable-parameter comparison.
