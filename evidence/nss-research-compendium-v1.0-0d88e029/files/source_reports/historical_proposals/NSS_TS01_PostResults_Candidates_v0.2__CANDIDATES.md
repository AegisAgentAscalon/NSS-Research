# Candidates after TS01 — proposed, not run

## 1. Priority: NSS-TS02-MW01, bounded maintained workspace alongside learned state

**Question.** After a task handoff or corrected evidence revision, can a small resident management workspace help a learned recurrent state recover and update *derived task progress* more accurately than an equally informed recurrent-only model and ordinary public indexing? A positive answer must survive controls for added parameters, storage and exact retrieval. The alternatives are extra capacity, a duplicate index, or an injected progress ledger. CM-02 already found W=I for deterministic references; TS01's eight-bit checklist is exactly tractable by a one-byte tracker. Repeating either comparison would add little. This successor needs a predeclared, bounded task with genuine handoff/revision consequences, not a general companion claim.

**Proposed task.** Retain two interleaved public tasks and an ordered milestone objective, then add changing goals, versioned public evidence, corrections/revocations and occasional conflicting or missing evidence. The next action depends on derived progress and the currently valid evidence revision. The append-only public journal is the authority: a candidate record needs matching task/scope and a causal, nonrevoked revision. UNKNOWN is justified only by observably missing or conflicting evidence under the frozen public contract; a controller must not be told that a hidden "no-cue" case has occurred. Byte-identical public histories with opposing hidden-intent labels are report-only counterfactual diagnostics, not a detectable case type or a gate-training target. Chat must freeze the exact event and authority grammar, task templates and labels before main-case generation. Every arm sees the same chronological public events and may query the same indexed journal. The workspace contains no evaluator progress bits, hidden intent, future events or gold next action; a “verified” marker must be grounded by an observed authoritative record.

**Minimal matched arms.** The frozen TS01 GRU **cannot read a new workspace**. A controller-only packet around it tests scaffolding. Candidate RW instead needs a new trained workspace-conditioned transition, with resident slots read during recurrent updates and written only from current public events/prior state. Freeze one native discrete-token vocabulary and embedding path *or* soft slots, with exact dimensions and costs; CM-02 ASCII bytes are not native tokens. R is recurrent-only with the same public events, task ID, archive API and decoder. R+ allocates RW's added parameters and resident bytes to ordinary recurrent state. S maintains public fields by ordinary rules; X is exact streaming progress plus indexed retrieval. S/X are deterministic controls, not additional learned fits. Workspace/state removal and same-network causal prefix replay are evaluation ablations, not separate trained arms. Supplied routing/filtering is identical; there is no learned-routing claim.

**State contract and controls.** A query reads without writing; per-task recurrent state and workspace persist across switches, while a correction changes only the addressed task after its public event. An episode reset clears both. Every cached reference carries source, scope and revision and uses S/X's public validity checker. All arms see the same causal prefix and can retrieve the same authoritative records. R/R+ have no hidden workspace; RW has no shadow ledger. Score stale acceptance, known-answer abstention, joint task progress and content separately. Exact lookup handles an observed payload; the learned question is whether versioned evidence is integrated into progress correctly after handoff.

**Economical review target.** Three configurations require separate training: R, R+ and RW. A provisional ceiling is five seeds × 1,000 updates **per configuration** = 5,000 each, 15,000 main optimizer updates globally, plus at most 300 development-only cost-probe updates across all configurations: **15,300 total**. If this is inadequate, revise the protocol before held-out generation; never silently raise updates after seeing scores. Freeze architecture, slot interface, optimizer, seed namespaces and workload after that host probe. Propose three development and five held-out families × four chronological sequences × six query checkpoints: 32 independent sequences, 192 unique occasions, 120 held out. Five seeds repeat occasions; they do not create 600 independent held-out cases. A primary pass is 192 × five seeds × three learned configurations = 2,880 logical neural decisions; replay, ablations, training forwards/backwards and deterministic S/X operations need separate caps and complete accounting. The host report must price training, inference/replay, exact controls, verifier, failed attempts and evidence. Provisional stop ceilings are two hours shared wall time, 3 GiB sampled process-tree RSS, a container abort below its hard cap, and 256 MiB new raw output. These are review targets, not runtime forecasts or authority to run.

**Decision rule to freeze.** Make primary joint task-state-plus-next-action correctness at each unique held-out occasion, with per-seed and per-family results; separately require zero observable stale/wrong-scope accepted references in the bounded safety screen. Compare RW versus both R and R+ on paired occasions, and against S/X for task correctness. Do not infer an advantage from RW beating only the no-history ablation. Set a meaningful minimum effect and an all-family consistency rule *after development but before held-out data are generated*; no threshold is chosen from TS01's perfect score or CM-01's 27-point gain. Compare carried RW with same-network prefix replay and charge archive scans; a recomputation saving is a different conclusion from superior accuracy. Claim overall efficiency only if a predeclared total-cost objective beats the exact/structured controls at matched correctness. Publish every negative and stop on leakage, source drift, invalid acceptance, nonfinite training or resource cap.

## 2. Conditional: workspace consultation and rewrite policy

If RW shows a specific benefit, compare resident-but-query-only consultation with consultation at every recurrent event, holding slot contents and public information fixed. Separately vary event-triggered versus periodic writes. Count writes, reads, retained bytes, model operations and lookup traffic. Residency alone is not evidence that the model used the slots. A result that disappears when cost-matched or that increases stale references falsifies the claimed policy gain. This is a later arm, not a reason to expand candidate 1 now.

## 3. Conditional: representation and repair

If a maintained workspace matters, compare structured slots, actual native discrete tokens and soft slots under explicit equal information/compute budgets. Test stale-reference invalidation and correction after an observed update. Report failure to repair derived state even when exact evidence is available. Token count, UTF-8 byte width and embedding dimensions are different accounting units; no compression claim follows from a short surface form. Preserve original NSS role separation and treat all representation changes as explicit new study arms.

**Next handoff:** ask Chat to critique and freeze NSS-TS02-MW01 only. Slot representation, final event/authority grammar, template/seed allocation, total forward bound, host feasibility and decision thresholds remain open freeze choices. No experiment follows without a separate user instruction.
