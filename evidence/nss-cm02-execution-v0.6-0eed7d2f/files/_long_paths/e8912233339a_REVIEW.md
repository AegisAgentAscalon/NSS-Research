# Review of Codex's CM candidate package — v0.2

**Recommendation:** use CM-02 as a bounded controller-continuity and freshness-policy comparison, not as a learned recurrent-memory test. The design is worth completing, but its useful outcome may be parity with an ordinary index. This is a proposal review, not an executed study or execution authorization.

## What Codex got right

The proposal replaces a weak scan-only competitor with an ordinary maintained per-task selection index. It fixes two resident task packets, makes the timeline genuinely 65 events (0–64), keeps repeated reader seeds separate from independent sequences, and requires causal prefixes, fresh replay, and full storage/update accounting. I agree with these choices. The literature notes are explicitly abstract-level mechanism distinctions, not evidence that NSS has learned those mechanisms. I reviewed those supplied notes; I did not perform an additional external literature review.

The most important correction to my earlier brainstorming is the treatment of a “recurrent state disabled” control. Q010 exposes a numerical read interface, not a persistent learned hidden state with a meaningful removal operation. Adding a switch that changes nothing would create a fake ablation. The useful control here is **workspace/archive versus conventional index/archive**, with an explicit no-selection-history ablation. A later native experiment needs an actual state transition and trained interface before a state-removal test can mean anything.

## The main unresolved interpretation in v0.1

The draft says “freshness,” but W and I deliberately leave their version-pinned selections unchanged after revisions and refuse a read until a new explicit selection/correction. This can establish **stale-reference detection**. It does not establish autonomous retrieval of current information. If the task's answer is the current record, the known-answer refusal is a recall loss caused by a conservative binding policy—not absent evidence or a learned-reader defect.

I preserved that symmetric pinned policy, and added one explicitly separate, **non-neural X_latest control** to proposed v0.2. It uses the same observed revision chain to follow a continuing entity and fetch its current payload, without inventing a correction of intended identity. It still returns UNKNOWN after deletion or unresolved conflict. It cannot solve a valid-but-wrong intended reference. This is a stronger ordinary-retrieval policy reference, not a fourth learned arm or an oracle.

This addition prevents the next report from crediting the workspace with “safe freshness” while overlooking a simple public-information route to the updated answer. The two semantics must remain separate: a revision-pinned reference and a current-entity request are different contracts. The new control is a **reviewer's proposal**, not something Codex already ran or originally specified.

## What a positive result would and would not mean

W/I parity through all prefixes and faults would establish bounded implementation continuity and validation correctness. Gains over O would establish the value of retained observable information. A lower counted resource metric could justify a narrow implementation-specific cache benefit. Any index advantage or tie is a valid result. The identical semantic state makes parity unsurprising; it is an implementation check, not evidence of two distinct cognitive mechanisms.

The scope remains limited: 32 sequences, six checkpoints each, five held-out families, exact software-maintained storage, and five frozen near readers. It cannot establish learned memory writing, native always-on tokens, state compression, long-horizon cognition, or the integrated NSS cores. “64 intervening events” is not a simulation of a human day. There is no need to keep enlarging this harness until it appears to prove those different claims.

## Changes made in the v0.2 proposal

1. Freeze four chronological templates (delay, freshness, correction/conflict, no-cue intent), all 65 event positions, six query checkpoints, exact noise assignment, deleted-target counts and diagnostic reuse. No actual episodes were generated.
2. Allocate 477 numeric seeds without drawing stimuli; audit them against available historical and reserved textual records. Missing historical random states and unmaterialized draws remain outside that audit.
3. Preserve W/I/O and the strong index; add X_latest only as the separately costed policy diagnostic described above. No nominal recurrent-state-off arm.
4. Specify a four-sequence / 24-occasion fixture using one near reader. Main plus fixture and fresh replay have a 3,936 distinct-forward upper bound under required reuse; the conservative non-reuse bound is 5,904, below the 6,000 ceiling. All counterfactual extra labels are scoring-only.
5. Tighten host and delivery ceilings: observed container limit is 4 GiB, so propose 3 GiB process-tree RSS plus a 3.5 GiB container-memory abort, rather than treating 4 GiB RSS as safe. Cap new raw evidence at 256 MiB and a single delivery ZIP at 64 MiB; do not duplicate prior archives.
6. Separate zero-observable-error engineering gates from known-answer refusal, no-cue intent failures and ordinary learned-reader errors. Those expected negative outcomes must not be safety-stopped away.

## Current verification and remaining work

Both historical dependencies are available with the identities expected by Codex. This review rehashed 628 CM-01 and 5,449 Q010 manifest members, plus all 12 manifest-listed proposal files. No model was deserialized or loaded; hashing model-file bytes is not inference. No CM-02 code, main data, numerical fixture or result archive was produced.

The proposed design is recorded now; an **execution source lock does not yet exist**. Future authorization must precede implementation and source freezing, the fixture and actual generated-input identity checks. The environment's inference compatibility is untested. These are real pending gates, not evidence that an experiment has run.

My priority after this bounded engineering pass is to specify the small native recurrent-plus-workspace experiment. That specification need not depend on a serialized cache beating an ordinary index. Its required evidence is different: a genuine persistent state, an update rule, allowed observations, training objective, matched storage/compute controls, and a meaningful state removal/reduction test. This review does not authorize training it.
