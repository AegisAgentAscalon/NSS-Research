## Proposed REV01 protocol for review, NOT_RUN

**Single intervention and competing accounts.** Freeze clip norm 1 (DC01 rule) versus 2 **only at the first valid feedback receipt whose label differs from the last publicly observed label for that same association and scope**. Both branches receive identical costed last-observed-label bookkeeping; a hidden reversal marker or trial index never triggers intervention. Warm learning, pre-change state, cue/receipt information, SGD rate and all later updates use norm1. Materialize the shared prefix once; **after observing and validating the changed receipt, but before applying its update**, fork the *same* parameters, pending cue graph/trace and public history. This isolates one correction's maximum step while preserving later retention/recovery. It contrasts dose with unchanged rule; it does not separately distinguish clipping from an equivalent learning-rate increase or recomputation direction. A second-small-step arm has a different update/work budget and is deferred. Record raw norm, applied factor, clipped direction, parameter delta, original decision margin and same-prestate exact derivative for G and specified approximate derivative for L.

**Fresh task and controls.** Use DC01's public cue/association grammar, 16-unit recurrent network and one identified receipt; keep cue-time parameters frozen until receipt, reset live state afterward, and score read-only queries. No hidden reversal marker or future label enters a learner. Build fresh cue-label mappings, receipt draws and seed namespaces with no complete or normalized overlap with the diagnostic DC01 failure set. Keep matched frozen no-online-update forks `N_G/N_L` and causal last-observed-label table X; X cannot know an unannounced reversal before feedback and its post-feedback exactness is an ordinary storage control. Test both G and L as separate methods; do not select a favorable learner or checkpoint. Use all negative rows. Maintain old association labels and probe them after each correction, not only at final endpoint.

**Units and split.** A modest candidate has four development and eight held-out independent base associations across two predeclared template families; each base is run under both clip branches from an identical pre-correction checkpoint. Four paired fit seeds repeat the same eight held-out bases, giving 32 paired base×seed comparisons per method, not 32 independent base tasks. Five predeclared read-only timepoints per branch: immediately before the changed-label receipt, after its first update, after the second same-label receipt, final focal probe, and old-association endpoint inventory. The first pre-feedback probe is expected to be surprised and must not be counted as a failed correction. Preserve both stable and reversed old-cue inventories; compare focal labels, probability/log loss and margins separately. Freeze which base/seed aggregates define the decision before held-out streams are instantiated.

**Decision rule to freeze.** The primary paired outcome is correct focal classification and log loss **immediately after the first changed-label update**. A candidate meaningful effect is at least one additional corrected base in each of three of four seeds, positive direction in at least six of eight held-out bases, and nonworsening pooled focal loss; this is a review target, not a post-hoc threshold. Safety/retention guardrails require no new wrong-scope update, no lost unrelated-old labels, and no predeclared material increase in old-cue log loss or reduced old-cue true-label margin after either first or second correction. Chat must set the numeric old-loss/margin tolerance from development, before held-out generation. Report before-feedback surprise loss, second-receipt recovery, G/L separately, unchanged norm-1 control and X/N results. If norm2 helps the first focal decision but degrades old-knowledge confidence, report the tradeoff rather than a pass. If both clips fail similarly, the dose hypothesis is not supported under this task; if gradients are not clipped in a new case, keep it in the denominator and report that stratum rather than censoring it. None of these outcomes changes DC01's frozen PASS labels.

**All-work accounting.** This is a new ledger, never reuse of DC01's 712 remaining attempts. Proposed schedule: four seeds ×two methods ×100 initial updates =800. Each of four development plus eight held-out bases has two shared norm1 receipt updates before the changed label, then each of two branches executes the changed receipt and three later receipts: `2 + 2×4 = 10` updates/base/method-seed. Thus 12 bases ×eight method-seeds ×10=960 condition updates; two 50-update cost probes add100: **1,860 planned original-pass attempts**. Full adaptive reproduction adds1,860, giving3,720 scheduled and a proposed **4,500 global attempt cap** with failed/in-flight work and reserve. Materializing the shared prefix consumes counted updates; no branch trains the next. Charge gradient/witness audits, read-only inventories, shared label bookkeeping, X/N queries, filler forwards, snapshots, checkpoints, source checks and replay separately; freeze cell/head/backward and byte limits from concrete shapes. The prior two-hour clock, 3GiB process-tree/3.5GiB container, 256MiB evidence and64MiB ZIP are provisional ceilings subject to actual-host feasibility, not forecasts. Fixture failure, leakage, nonfinite update, source mismatch or cap breach stops under a frozen rule; poor accuracy is a retained scientific negative.

Keep the v0.4 storage stop and v0.5 successes intact.
