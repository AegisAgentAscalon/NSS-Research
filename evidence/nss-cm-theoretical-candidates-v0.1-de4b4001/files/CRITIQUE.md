# Independent design critique: CM-02 proposal

CM-01 supports a narrow result: a public reference manager can reconstruct a canonical query and improve the frozen reader on noisy bound-close cases. Its gain is concentrated at sigma .2 (17/100 to 72/100), with no low-noise gain (71/100 to 70/100); public exact lookup is 40/40 on valid bound-close records. These observations fit query denoising/reference assistance as well as any persistent-memory account. CM-01 did not give the stateless Q010 readers a recurrent hidden-state interface, did one learned read per case, and did not test long chronological continuity. CM-02 as drafted therefore tests controller/archive continuity and freshness, not learned recurrence or token compression. Do not add a nominal “state-off” arm that changes no input or transition.

Before protocol freeze, resolve four material points:

1. **Equal-information efficiency control.** A full journal scan at every query is a deliberately expensive Arm A. Replace it as the main comparator with a materialized per-task current-selection index using the same public events and update rules; retain scan only as a correctness/cost reference. State whether W is one active-task packet or has per-task snapshots, what survives a switch, and how each query’s current task/scope is supplied and validated. Count index rebuild/update work and bytes. The public exact-lookup control is stronger on valid bindings; score it separately and include its non-neural lookup/storage costs.

2. **Chronology and stale semantics.** With selection at event 0, 64 intervening events require a 65-event stream. Reconcile this with “up to 64 events” and the six query checkpoints. Also state whether W observes a revision/deletion and refreshes or invalidates the packet before the next query, or whether the study deliberately presents a stale packet. Do not conflate those cases. Abstaining on a revised-but-still-known record is a recall loss; UNKNOWN after deletion can be correct. Controller updates may use only events already observed, never future answers, protected origin or query labels.

3. **Arithmetic and sample unit.** The draft’s 32 sequences × 6 occasions = 192 unique queries is consistent; five fixed model seeds are repeated evaluations, not 960 independent episodes. Keep per-sequence/per-family paired results and base claims on the 5 held-out families (20 sequences); 3 development families contain 12 additional sequences. For three neural arms, 192 × 5 × 3 = 2,880 logical one-stage forwards; one full replay can reach 5,760, below the 6,000-call ceiling but with little overhead. If adding a fourth neural index arm, the maximum becomes 3,840 before replay and 7,680 with replay, exceeding that ceiling; revise scope or cap. Report cached identical forwards separately from logical decisions and non-neural lookups.

4. **Full memory accounting.** A 56-byte packet is only one component. Compare total retained journal, per-task index, K/V, catalogue, query, workspace, snapshots and metadata, plus bytes read/written, lookup or scan work, neural calls and measured latency. If W and archive-only arms have equal correctness/freshness but W costs more overall, the data establish continuity, not memory efficiency.

The distinction among task correctness, safe abstention, public-bound truth and protected no-cue origin is appropriate; preserve it. Sol’s final revision addresses the index-vs-scan, task-slot, symmetric stale-validation and 65-event timeline issues. Root’s final acceptance will add causal-prefix isolation and fresh replay without reusing the original inference cache. Remaining freeze choices are exact event/query order, unused seed-family proof and end-to-end host caps; root can disposition these without another review cycle. No execution or Q010 role change is authorized.
