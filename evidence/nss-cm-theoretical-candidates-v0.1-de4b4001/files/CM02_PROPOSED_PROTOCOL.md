# CM-02 continuity comparison — proposed protocol for review only

**Question.** Across delayed queries, task switches, revisions and corrections in one evolving catalogue, does a persistent public-reference packet preserve safe, fresh access, and does it offer any cost advantage over an ordinary maintained selection index? Public-history reconstruction supplies a separate route/cost reference. The fixed Q010 near readers have no native recurrent hidden state. This study would test controller/archive continuity, not a learned recurrent-state contribution.

**Frozen interfaces and arms.** Keep the five saved near-reader exports and one-stage Q010 K/V/valid/query input, shared resolver, exact decoder and numerical verifier fixed. Each arm observes the same ordered registration, selection, correction, conflict, revision, deletion and task-switch events. The protected origin/answer ledger is reserved for scoring. Arm W retains one 56-byte workspace packet **per task** (two task packets, 112 serialized bytes), plus the full public journal and indexed record/binding archive. Select/correct/conflict events update the packet for their task; switching tasks preserves both packets. Revision/deletion does **not** silently refresh a selected packet: both W and the index control validate its revision/active status against the current record at query time and abstain if stale. Arm I retains the identical public journal/archive and an ordinary materialized per-task latest-selection table, but no workspace packet; it updates that table on the same selection/correction/conflict events and applies the same validation and canonical-query route. Charge its table bytes and update work. This is the strong equal-information control. A full-journal scan is a non-neural reference for route and access-cost auditing; it does not add a distinct model arm. Arm O sees events but retains no prior selection/journal at query time and uses original Q with current K/V and catalogue; it is an information-removal ablation. Route lookup validates current public task ID and scope before binding/record use. No arm has additional learned recurrent or task-state vectors. Cache inference outputs for byte-identical numerical inputs while counting logical decisions and actual calls separately.

**Controls and independent units.** Public exact lookup may retrieve only an observed payload under a valid, current public binding. It has no fuzzy fallback and returns UNKNOWN without one. A privileged exact-owner control, if retained, is never pooled with public arms. Make three development and five held-out *new* episode families with disjoint catalogues, graph/event seeds and seed domains from CM-01 and Q010 evaluation. Use four chronological sequences per family: 32 unique sequences total. Each sequence keeps one sixteen-record catalogue and interleaves two tasks over events numbered 0–64 (65 events), with six queries at checkpoints 0, 8, 16, 32, 48 and 64 (192 unique query occasions). In a declared long-delay subset, selection at event 0 survives 64 subsequent event transitions, including other-task events, without changing the target binding. Separate sequences carry revision/deletion, valid correction, conflict, and no-cue wrong-binding cases; do not combine incompatible histories merely to fill a checklist. Balance and freeze the schedule before generation. Feed identical event bytes to every arm. Five fixed near-model seeds repeat evaluation of the 192 occasions, not 960 independent sequences. Reserve held-out families before development; publish seed identities and generation manifest before scoring. Do not tune on held-out results.

**Outcomes and falsifiers.** Primary safety: an accepted binding must match the independently reconstructed *observable* public binding at every query; target zero observable stale, wrong-scope, deleted or detectably wrong acceptances in this bounded screen. Count safe abstentions losing updated-known recall separately from correct deletion UNKNOWN. W and I should show exact route/canonical-query parity on clean bindings and the same declared stale-validation behavior; investigate any divergence. Report per-sequence/family answer accuracy for valid known, missing/deleted, close/noisy and no-cue origin cases, with W–I and W–O paired differences. Do not fit a competence target to CM-01's 27-point gain. W–O benefit shows retained-public-history value. W–I parity with lower **total** bytes/updates/lookups/time would support a workspace cache advantage; equal or worse cost would not. No-cue opposite-truth pairs are report-only information limits, never optimized acceptance targets. Whole-map integrity and binding safety remain separate from answer content; zero observed safety failures in this small sample is not a population guarantee.

**Cost and stopping bounds, to be reviewed against Chat's actual host.** At most 192 unique query occasions × five fixed models × three learned-read arms (W/I/O) = 2,880 logical reader decisions before replay; the full-scan and exact-lookup controls are non-neural. Identical-input caching may reduce physical calls. One exact replay plus a small fixture must stay below 6,000 physical model calls, 2 hours of measured wall time, 4 GiB process-tree RSS and 2 GiB new output. These are stop ceilings, not forecasts. Record setup, event processing, journal/index/packet bytes, active retained state, lookup count/returned bytes, scan work, neural calls, output bytes and replay separately. Stop on source/seed drift, protected-truth access by a producer, an unexpected safety acceptance or resource cap; preserve the failure and all negative cases. Any changed protocol needs a new version before held-out execution.

**What to ask Chat now.** Review this proposal as a protocol only. Resolve event/checkpoint balance, route equivalence, independent sequence/seed allocation and realistic measured host caps; return a frozen proposed protocol and critique with exact source/input identities. Do not generate main cases, load models, execute CM-02, train, or publish a result archive until the user separately authorizes execution. No NSS role or architecture replacement follows from this proposal.

**Freeze requirements.** The shared initial catalogue must be built from a public registration prelude, with its work charged, before event 0 selects the delayed target. At every checkpoint all controllers, reference scans and retrieval indexes may access only that prelude and the observed event prefix; no future-event access. The held-out set is five families / 20 sequences / 120 query occasions; the development set is three families / 12 sequences / 72 occasions. Publish the exact event templates, numeric seed allocation and query/noise schedule before held-out generation. Those details remain protocol-review choices, so this proposal is not execution-ready. Public exact lookup receives the same currently validated binding and prefix; report its full lookup/state costs and content scores separately. Inference caches include the exact model identity and numerical inputs in their keys. Replay must freshly compute the distinct inputs with a new cache, not reuse first-pass outputs. A stopped run is incomplete and its failure remains reported; do not present partial denominators as a completed pass. No optimization or model updates occur in this proposed study.
