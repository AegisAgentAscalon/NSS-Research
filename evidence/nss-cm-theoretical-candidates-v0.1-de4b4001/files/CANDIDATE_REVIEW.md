# Context-management theories after CM-01 (proposal v0.1)

**Evidence boundary.** CM-01 v0.2 is a bounded fixed-weight interface pass. Retained-row checks confirm the near reader's held-out close-identity result, 88/200 with the original query and 142/200 with the reference workspace: 40 unique episodes evaluated with five fixed models, with positive gains in all five families. The checked noise split shows almost no low-noise benefit (71/100 to 70/100) but a large high-noise benefit (17/100 to 72/100). Public exact lookup scored 40/40 separately on valid bound-close and bound-known episodes. The study reports no training, native recurrent tokens or memory compression. Its 512 labeled cases are isolated rather than one long sequence sharing an evolving catalogue; the archive reports 448 distinct public inputs, including deliberately duplicated opposite-truth pairs. Q010-P1 remains a separate unrun information-audit proposal. These results justify a focused continuity question; they do not authorize changing the frozen Primary, Secondary, Tertiary or advisory Validator roles. Sources: `Research/NSS_CM01_Execution_v0.2.zip` (`REPORT.md`, `STATUS.json`, `protocol/PROTOCOL.json`) and `.research_review/CM01_v0.2_20260924/primary_check.json`.

## 1 — Recommended: public-reference continuity and freshness

**Competing accounts.** Under the reference account, a small resident packet helps keep a selected public binding available through unrelated events; a validated archive supplies the canonical query or exact observed payload. Under the weaker denoising account, CM-01's improvement comes only from replacing one noisy query at read time, with no value from persistence. Under the failure account, a stale packet is dangerous after a revision, deletion, task switch or conflicting correction. CM-01 tested validation/refusal in isolated cases and a 32-event software persistence unit test, but not a continuous multi-query episode with interleaved tasks and changing facts.

These mechanisms can coexist: successful reference retention can enable query denoising. CM-02 distinguishes failure modes and compares implementations; it cannot establish a unique cognitive mechanism when the workspace and ordinary index retain equivalent state.

The next smallest informative study is CM-02 as specified separately in `CM02_PROPOSED_PROTOCOL.md`: actual chronological public event streams over one catalogue; fixed Q010 near readers; a persistent per-task workspace plus archive; an equal-information archive controller with an ordinary maintained per-task latest-selection index; and a clearly marked original-query/no-history information-removal arm. A full-journal scan serves only as a non-neural route and cost reference. Compare answer correctness, accepted wrong bindings, safe abstentions that lose known recall, freshness after changes, and full memory/lookup/latency cost per *unique chronological episode*. Public exact lookup is a control for valid observed payloads; privileged exact-owner remains labeled separately if included. On clean bindings, matching routing with lower *fully accounted* workspace cost would support a cache/economics role, not unique cognitive competence. The strong index may match or beat the workspace; that is a valid result. On stale revisions, both public caches should validate against the current record and abstain, with updated-known recall loss recorded. If the workspace accepts stale/wrong bindings, the continuity claim fails even when some answers are right by chance.

The no-history arm discards public selection evidence by design. A gain over it measures the benefit of retained observable information and cannot establish that a workspace is necessary. No arm may use the protected intended identity, source graph, answer or hidden origin when selecting a reference. Public exact lookup may return a payload only under a validated public binding. No-cue opposite-truth pairs remain an information-limit diagnostic: CM-01 reports identical public histories and numerical inputs for opposing labels, so any deterministic rule using only those inputs must err on one side of each pair. Safety and content accuracy must be scored separately.

## 2 — Conditional: residency, consultation and refresh economics

If CM-02 shows that the workspace remains valid across chronological events and provides some measured access benefit, a later CM-03 can vary one factor at a time: resident packet versus on-demand reconstruction, reading it every relevant step versus only at a declared query, and event-triggered rewrite versus periodic refresh. Keep the same public archive and observable history available to each equal-information arm. Measure total bytes, retained journal/index, lookup traffic, controller work, neural calls and stale-binding incidents. A 56-byte serialized packet is not a 56-byte system: CM-01 reports roughly 12–14 KB per-case journal, 13–14 KB directory, plus index, K/V, catalogue and query. Structured and serialized interfaces matching in 7,680 archived comparisons shows encoding parity, not a learned token-budget advantage. The falsifier for a claimed efficiency win is equal or greater total cost at equal correctness and freshness. Native 8/32/64 model tokens remain outside this fixed-weight comparison.

## 3 — Deferred: extra task/recurrent state and learned native memory

There is currently **no native recurrent hidden-state interface in the frozen Q010 readers**. A nominal “recurrent state disabled” switch that changes no model input or transition would create two identical arms and cannot test recurrent contribution. CM-02 should therefore use a workspace-plus-archive arm with no extra learned task state and state plainly that it tests controller/archive continuity. A later study can assess an actual additional state only after specifying its update rule, permitted observations, retention across switches, information budget, and an independently meaningful removal operation. Compare with a workspace-plus-archive-only control holding public evidence and compute as closely matched as possible; otherwise an apparent recurrent benefit could be extra storage or privileged information. Learned model-managed writing, native token compression, delayed credit and low-bit learning require new models, training protocols and separate authorization. They are hypotheses, not interpretations of CM-01.

**Ranking rationale.** CM-02 closes the immediate causal gap between CM-01's independent cases and a persistent reference; CM-03 is useful only after continuity is credible; native recurrent memory requires new implementation/training and should not be inferred from a deterministic packet. The next delivery should be a finalized protocol for the user to inspect and relay. This draft is analysis, not an instruction to execute a study.
