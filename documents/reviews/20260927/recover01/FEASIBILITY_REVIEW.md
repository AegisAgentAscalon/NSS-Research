# RECOVER01 feasibility review

RECOVER01 is feasible as a bounded recovery diagnostic using only the four retained final SURFACE01 parents. It must be a new, separately locked study: SURFACE01 v0.1's protocol intentionally blocked adaptation after any parent's competence failure, and `source/adapt.py` asserts `PARENTS_ADMITTED` before it starts. The new user direction permits a baseline with known errors to enter a recovery study; it does not change SURFACE01's historical `STOP_BASELINE_COMPETENCE` result or authorize execution. Source and parent identities are enumerated in [`parent_sources.json`](parent_sources.json); the complete source is [`Research/NSS_NBR02_SURFACE01_Execution_v0.1.zip`](../../../Research/NSS_NBR02_SURFACE01_Execution_v0.1.zip).

Use one independent model copy per arm from each exact `parent_{4101,4102,4103,4104}_2000.pt`. Keep the existing shared transition-plus-readout parameter surface in every learned arm: source path U trains both `cell` and `head`; path F is the different frozen-cell/readout-learning control. Each copy must start from byte-identified parent weights, with no tensor aliases. Preserve all four parents, including 4103's known idempotent false-DONE failure, as paired blocks. Do not apply an all-parent-perfect admission gate to this recovery question.

The old recipe gives a concrete B-learning treatment: 64 optimizer steps; each step scores all eight zero-state B cues and uses targets `arange(8) % 2` with the selected cue index flipped. Existing correction indices are 0, 3, 4 and 7. I recommend retaining those four predeclared indices as within-parent blocks instead of choosing a favorable cue after viewing results. The four arms at each parent×cue block are U (unchanged), L (64 B-only steps), R (64 A-only repair steps), and LR (the same 64 B steps followed by the same A-only repair schedule). This is 4,096 optimizer applications across 16 blocks, before evaluation; one-cue scope would be 1,024 and must be selected before examining outcomes. Cue blocks are repeated contexts, not extra independent parent seeds.

For R, sample 64 distinct batches from that parent's retained 2,000-batch A training corpus, fixed before fitting using `default_rng(500000 + parent_seed).choice(2000, 64, replace=False)`. Each source batch contains 32 A streams of 32 events, for 2,048 presentations / 65,536 event labels per repair phase. Use exactly the same ordered batch indices in R and LR. Repair loss is mean A cross-entropy over those events, with no B logits, labels, or B gradient. This requires an explicit A-only update path: current `common.update()` always includes B loss, and when A data is supplied it mixes 0.5 A + 0.5 B. Calling it unchanged for R would contaminate the control. Keep the shared learning rate at 0.003, Adam betas (0.9, 0.999), epsilon 1e-8, zero weight decay, foreach/fused off, and global active-gradient clipping at 1.0, matching the source recipe. Start each arm with fresh Adam state; in LR reset only Adam moments/counter at the B→A boundary while preserving weights. Record both phases' states and counters. This estimates weight-mediated recovery without optimizer-momentum carry; it does not test persistent optimizer continuation.

Interpret paired contrasts narrowly: L−U estimates B-update effects; R−U estimates A repair alone; LR−L estimates the incremental effect of matched A-only repair after B learning. LR−R combines order and an additional B phase, so it is not a factorial interaction or equal-budget architecture comparison. Report corrected-cue and all-eight-cue behavior after L and LR to expose collateral loss of the seven unchanged B labels.

Freeze and score the entire original admission panel in every arm, including all histories previously correct and the six known 4103 errors. Report full-panel rates and, separately, transitions for baseline-correct histories/errors (recovered errors, retained errors, newly introduced errors/false-DONE); never score only the six failing cases. Also freeze a new recovery-specific panel before any update, with distinct per-parent generation seeds (for example 400000 + parent seed) and retain its fixture hashes. The reused admission panel is paired diagnostic evidence, not independent confirmation. Measure CARRY and REBUILD separately: CARRY starts from the original parent's pre-update prefix state; REBUILD replays that same prefix using adapted weights. They answer different state-continuation policies. Validate implementation/reference numerical agreement independently under a prospective predeclared contract; do not call numerical agreement behavioral recovery or silently inherit/relax a failed historical threshold.

No new parent fits are needed. A preflight should estimate the 4,096 updates plus paired evaluation against the existing 1,800-second, 2-GiB RSS and 512-MiB evidence ceilings; stop before updates if infeasible, and retain every baseline error and partial result. This remains a candidate protocol only. It needs its own source/fixture lock, confirmatory panel separation, resource estimate and explicit Chat dispatch before any run.
