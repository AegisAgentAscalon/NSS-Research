# Independent solution hypotheses for NSS

This is a bounded critique of the accepted architecture review and Chat handoff, not an architecture decision or experiment dispatch. The scientific pause remains in force.

## Strongest alternative to the provisional bottleneck account

My leading alternative is that task competence and problem specification, not lifecycle control, limit NSS today. Small learners face tasks whose binding, depth, revision, and continuation exceed their demonstrated training distribution and capacity. Memory-like failures can therefore reflect representation, optimization, curriculum, or an ambiguous target rather than conflicting memory roles.

Several results fit: Q001 recurrent recall collapsed with delay while full-tape attention retained more early cues. In Q003, nearest-prototype beat learned repair; in Q009, exact ownership preserved writes but learned readers failed on near-identity cases where exact traversal succeeded. TS02/03 retained metadata while derived progress was poor, and CKA01 attributed some TS03 weakness to incomplete fitting and transfer. Better ledgers do not supply missing representation or curriculum.

STATEBRIDGE shows incompatibility, but not that weight drift is the chief system bottleneck. A boundary-readable vector may encode the old operator’s latent coordinates, not operator-independent task meaning. Later failure could reflect non-identifiable state, inadequate migration rules, insufficient 16,329-parameter capacity, or conflict between A retention and B acquisition. The failed whole-prefix gate must remain failed, but its necessity for useful behavior is untested.

“Unrestricted adaptation” is not diagnosed: the studies use bounded synthetic tasks and declared update surfaces, with no matched comparison of unconstrained updates against isolated adapters. Nor do results show that mixed duties cause most failures. A stronger alternative is insufficient capacity, curriculum, or identifiability, with migration and role separation as risks still to isolate.

## What the current results do not diagnose

The record does not separate capacity from learning-rule failure, curriculum mismatch from interference, impossible tasks from model error, latent-state identifiability from migration error, or readout damage from recurrent damage. The saved readout-by-recurrence factorial has not run. PINNED keeps A but answers obsolete B; adaptive carry and rebuild fail adequacy, so none is a successful equal-capability control.

No matched-cost study tests extra scale, more curriculum, different optimization, or simpler hybrid solvers. A new protocol may decide whether the old gate is product-relevant, but cannot delete its recorded failure. Evidence does not establish distinct parameter sets for Primary, Secondary, and Tertiary, nor separate role benefits from extra compute, data, routing, or duplicated capacity.

## A candidate beyond the tri-core lifecycle

Test **versioned skill capsules** as an alternative to a global tri-core update-and-sleep cycle. Use one frozen generalist backbone, an exact provenance-bearing event/evidence ledger, and a small separately versioned adapter or readout for each declared skill family. A simple router selects the capsule; an external deterministic checker validates the task-specific invariants. Task state is recorded as an explicit, replayable event summary bound to the backbone and capsule versions. Updating one capsule cannot silently alter other skills. If a capsule cannot safely resume a task, retain the old version or defer publication.

This does not assume that more modules are better: capsule count, routing errors, adapter storage, optimizer state, replay and duplicated examples can erase any parameter savings. It is a distinct candidate because learning is scoped by skill and published as a local delta; it does not require separate always-participating cognition roles or a nightly consolidation event. It should be compared with both a frozen/retrieval baseline and the proposed lifecycle under matched data access, capability targets, and full costs.

## Minimal ranked test sequence

1. **Validate that the task is learnable and the evaluator is informative.** Freeze task generators and an exact solver or oracle for small cases. Include near-identity cases with sufficient information, unseen but solvable cases, and deliberately ambiguous or contradictory cases that should be rejected. Verify that injected defects fail the intended gates and that clean controls pass. Preserve the failed STATEBRIDGE whole-prefix result; define a new version’s trajectory tolerance and behavioral continuation targets before any run.

2. **Screen competence before blaming lifecycle.** For one task family, compare the current small learner with a larger-capacity or better-staged curriculum condition, a no-weight-learning control exposed to the same examples and compute but using exact retrieval, and a learned update condition. Keep examples, evidence, seeds, inference budget, and test access paired. Require an acquisition gate on B and held-out transfer before interpreting old-task A loss. If no arm acquires B, the state-preservation comparison is not yet diagnostic of adaptation interference.

3. **Localize the update surface.** If B acquisition is established, run the saved shared/copied-readout × adaptive/frozen-recurrence comparison with the matched no-learning/retrieval control. Score A carry and history-rebuild, B acquisition and retention, nearby distractor skills, and real end-to-end resume behavior. Use independent seeds and retain every checkpoint and failure. If the learner cannot solve the task under any update surface, return to task/capacity design rather than declaring a lifecycle failure.

4. **Compare the capsule candidate only after a viable learner exists.** Against the tri-core lifecycle, match successful new-skill acquisition and old-skill thresholds first, then compare task interruption and resume. Count backbone, adapters, evidence/event storage, gradients, optimizer and trace state, activations, checkpoints, rollback copies, candidate preparation, training, replay, evaluation, routing, migration, latency, and energy. Report peak and retained memory and correction-to-use delays. Do not claim low-bit or modular savings from nominal parameter counts alone.

This ordering makes a negative result useful: it can reject the task contract, the learner, a particular update surface, or the more expensive operating design without conflating them. Any proposed run still requires a named versioned protocol and user dispatch.
