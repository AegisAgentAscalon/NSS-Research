## ELI5 and question

Think of four learners who mostly know an eight-item checklist. Three passed their own checklists perfectly. The fourth made six wrong “all done” calls in one checklist, while getting 8,186 of 8,192 scored answers right. The old admission rule was right to stop the planned comparison when one learner violated its zero-false-DONE condition. RECOVER01 does not rewrite that result or relabel that learner as passing. It asks a different question: if we now deliberately keep all four unchanged learners, can each acquire one new cue association, and can a small ordinary replay of the old checklist behavior reduce any old-task damage from that update?

The four matched branches are: **U**, untouched; **L**, new-B acquisition only; **R**, old-A replay repair only; and **LR**, the same new-B acquisition followed by the same A-only replay repair. The main questions are whether the B association is acquired, whether B learning creates A errors relative to each learner's own U branch, and whether A-only replay repairs pre-existing or update-induced errors while retaining B. This is a fixed-budget mechanism diagnostic, not an equal-compute architecture comparison or system qualification.

SURFACE01's report and the bounded local archive audit agree that only parent 4103/idempotent failed its family gate: 2,042/2,048 suffix events and 63/64 complete histories were correct, with six false-DONE events at events 17–22. Its mask remained 223 and target remained item 5; this was a fixed-weight semantic failure, not update-induced forgetting. All four parents passed the B screen. The exact failing history is exposed development evidence. The full archive and retained arrays have passed local CRC/manifest and numerical recount checks; the reference replay and tensor-level checkpoint hash results remain study-reported. ## Frozen cohort, branches and training recipe

Use the four existing final parent checkpoints 4101–4104 exactly as retained. Do not refit parents, replace seeds, or filter out 4103. The original SURFACE01 admission decision stays `STOP_BASELINE_COMPETENCE`; RECOVER01 admits the imperfect cohort under a new recovery question. Report every parent and focal-cue result, including failures. No all-parent pass condition may suppress other data.

Use one adaptive surface: the complete shared GRU cell and nine-class head are trainable, matching the source's ordinary U update path. Keep architecture, input encoding, and inference interface fixed. RECOVER01 prospectively expands the old B-correction targets from historical cues 0, 3, 4 and 7 to all eight cue rows 0–7, one focal cue per branch block. For focal cue `c`, preserve the source target construction: start with `arange(8) % 2` and flip only row `c`. This is a declared versioned scope expansion, not a claim that v0.1 ran all eight. At B checkpoints, `b_logits()` scores the same eight zero-state cue tokens in order.

For each parent and focal cue, fork the same source-pinned weights, empty Adam initialization, and per-context task state before branches diverge:

- **U:** no updates; it anchors that parent's A and original-B behavior.
- **L:** 64 B-only acquisition updates. Each step minimizes mean cross-entropy across all eight zero-state B cues with the focal target flipped. No A loss is present. This matches `adapt.py` calling `update(model,opt,correction=cue)` without A tokens; the helper's mixed A/B path is not used.
- **R:** 32 old-A replay updates from the unchanged parent. It never receives the new B target or B loss.
- **LR:** execute the same 64-update B prefix as L once, then branch at its step-64 weights into L (hold) and LR (repair). Run the same 32 A-only updates as R. Reset Adam moments/counter at the B-to-A boundary, matching a fresh repair optimizer; R also starts its A-only phase with fresh empty Adam. This isolates the repair weight schedule while excluding optimizer-momentum carry, which must be stated as a limitation.

Use source Adam settings: learning rate 0.003, betas (0.9, 0.999), epsilon 1e-8, zero weight decay, foreach/fused disabled, and global active-gradient clipping 1.0. Select 32 distinct batches from each parent's retained 2,000-batch A corpus with NumPy PCG64 `default_rng(500000 + parent_seed).choice(2000,32,replace=False)`; preserve returned order and serialize/hash the selected indices. Each batch has 32 streams of 32 events. Repair minimizes mean A cross-entropy over all 1,024 event labels per step, from reset scratch state. R and LR use identical ordered batches across focal cues. Development/confirmation histories never train repair. The existing `common.update()` always includes B loss; R/LR need an explicit A-only path, verified for labels/loss/gradients. [source: `source/adapt.py` 75–88; `source/common.py` 181–204]

Optimizer accounting: 4 parents × 8 focal cues = 32 blocks. Compute each 64-step B prefix once and fork its weights to L and LR: 32 × 64 = 2,048 B-schedule applications. The 32-step A repair runs independently in R and LR: 32 × 32 × 2 = 2,048 A-only applications. Total maximum main work is **4,096 actual optimizer applications**, excluding inference and file checks. Duplicating the B prefix for LR would cost 6,144; the run receipt must record shared-prefix lineage and actual applications. No additional tuning runs or parent refits are included.

## Prospective criteria and interpretation

These are proposed reporting criteria, not retrospective edits to SURFACE01's gate. For each parent × focal cue, call B **acquired** only if all eight cue outputs match that block's target vector and the minimum assigned target score is at least 0.80 at step 64. Apply the same criterion after LR repair to call the B mapping **retained**. If it misses, keep the A measurements and label acquisition or retention failure; do not discard the branch. The B panel is the fixed cue probe, not a broad estimate of generalization.

Report every new A error. A **material-harm flag** means any false-DONE at a position without false-DONE in U, or a decrease greater than 1 percentage point in event or complete-history accuracy, computed separately for each family. **Stable learning within tolerance** means B is acquired and no material-harm flag occurs; disclose remaining smaller losses and do not require repair to improve it. **Full observed recovery** means L introduced errors, LR corrects every L-induced error, introduces no errors at other U-correct positions or new false-DONE anywhere, has per-family event/history accuracy at least U and false-DONE counts no higher than U, and retains B. This is return to a possibly imperfect baseline, not perfection. **Partial recovery** means fewer L-induced errors but unmet full-recovery criteria; report newly introduced errors and B retention alongside it. **Tradeoff/new harm** flags remaining or new damage, or lost B learning; it may coexist with partial repair. **Acquisition failure** means the B criterion misses; keep A results. **Technical stop** means invalid/incomplete evidence from a declared integrity/execution/resource condition, not scientific failure. Show all rows, not one cohort verdict. Cue blocks are repeated contexts within four parent seeds, not 32 independent model replications.

Report pre-existing-error repair separately: among positions wrong in U, show which became correct in R and LR, and what new errors those arms introduced. If CARRY fails while REBUILD succeeds, do not fold that into model recovery; retain the state-policy split and make state-anchored repair or translation a later candidate. If both fail with fitting weakness, consider flag-level or oracle-anchored stability supervision as a new objective study. If full-model updating creates material harm despite acquisition, a restricted update surface can be a later versioned comparison. Do not add those candidates to this pass or change the fixed gate after seeing outcomes.

## Candidate map

| Candidate | Hypothesis and discriminating result | Scope |
| --- | --- | --- |
| Ordinary A replay | LR repairs L-induced A errors while retaining the corrected B mapping; R shows how much replay merely improves the old baseline. | Test now. |
| State-anchored repair | Revised weights need training to operate on saved pre-update states; a CARRY failure with REBUILD success motivates this. | Later separate protocol. |
| Flag-level / oracle-correct stability supervision | Better explicit pending-item learning addresses fixed-weight semantic errors; motivated if U/R weaknesses dominate. | Later controlled objective comparison. |
| Restricted adaptive surface / stable backbone | Limiting shared-operator changes reduces interference while still allowing B acquisition. Frozen learning that cannot acquire B is not a success. | Later if full-surface acquisition creates damage. |

A successful LR result supports only this fixed replay budget. A failed result does not disprove all replay schedules. These later candidates are alternatives, not automatic follow-on runs.
