2. Broader-question map

Research area

Broader question

Current evidence-based answer

Persistent state, memory, binding, and compact context

How can NSS preserve, bind, recover, and use the right state/evidence across long event streams without confusing identity, absence, revision, or scope?

Exact ownership, scope, versions, and deterministic retrieval are strong bounded controls. Small learned recurrent state can preserve narrow task progress, but close-identity binding, noise robustness, and derived progress remain recurring failure surfaces.

Learning, interference, repair, and model revision

How can NSS acquire useful changes while measuring collateral damage, repairing old competence, preserving unfinished work, and deciding whether a candidate model should be accepted?

Useful updates can be learned, but shared-parameter changes can damage old behavior. Ordinary replay is a strong mechanism; endpoint recovery can hide transient harm; saved task state can become incompatible with revised weights. A two-night balanced candidate cycle is promising but not long-run qualification.

Hierarchical sparse attention and segmented context

Can NSS use a bounded active working set and selective hierarchical computation to reach more information or reduce redundant work while preserving exact evidence?

A three-level hierarchical reader and segmented executor were implemented. HSA helped learning on the bounded rule; exact multipass execution can process evidence larger than the active tile. Ordinary caching/streaming explains much of the benefit, so unique superiority of the custom segmented policy is not established.

Output construction, planning, checking, and editing

Can NSS construct maintenance artifacts incrementally and reliably, and do alternative output mechanisms offer a practical advantage over supported autoregression?

Plan/check/edit/commit is useful as a workflow, but the tested segmented-diffusion implementation did not earn a practical advantage over equally supported autoregression. Direct parallel structured generation remains only a specified future probe.

Language/evidence reader, handoffs, and quiet-time preparation

Can a small reader understand supplied records, resume work from handoffs, select relevant evidence, and benefit from preparation without confusing retrieval failure with interpretation failure?

The internal small-English readers are useful research instruments but weak general readers. Retrieval/handoff infrastructure can preserve information and question-aware selection can improve answers, yet correct evidence does not guarantee correct procedural use. General prep sheets and support-loss training did not solve the problem.

Bridge/orchestration integration

Can the positive NSS mechanisms be wired around a conventional language-model interface with explicit state, exact records, permissions, receipts, and recoverable task continuity?

A dummy NSS bridge can wire a language-model interface, exact journal/permissions/receipts, recurrent advisor, and restartable task state. It demonstrates integration wiring and containment, not a trained general orchestrator.

Low-bit model quantization

How far can NSS reduce model-weight precision while retaining useful behavior and exact executable representation, before later optimizing training and post-learning repair?

Two-bit matrix weights are the strongest current model-quantization result. After preparation they retain near-perfect bounded checklist performance with a true packed representation. Ternary packing is smaller but the tested preparation/conversion routes did not retain adequate whole-task reliability. Training-state optimizations are recorded but intentionally separated from the current model-quantization milestone.

Program controls, evaluation, and documentation

How do we preserve evidence boundaries, fair tests, source identity, roadmap decisions, and drop-in reproducibility for the larger research program?

The program now has explicit evidence boundaries, failure retention, test-validity review, a running priority ledger, and consolidated subproject records. Planning artifacts are not scientific executions.

4.1 Q001

Status: COMPLETED_DIAGNOSTIC

Evidence: Executed study

Specific question

Can a tiny memory keep a symbol while distractions arrive?

System: Five-seed synthetic memory pilot: GRU, soft-gate, hard-gate, full-tape Transformer, and exact-memory control.

Methodology: WRITE/DISTRACTOR/QUERY streams tested short competence and long-delay recall, including 128 distractors and a post-pilot low-gate intervention.

Main result / key metrics: GRU/soft-gate/Transformer passed short task in 5/5 seeds; at 128 distractors early-cue recall fell to 0.39% GRU and 0% soft-gate; exact memory stayed perfect.

Checklist result: Short tasks worked; long distraction exposed decay. Exact memory remained a strong control.

Interpretation / limits: Initial feasibility only; exact memory is a strong non-neural control; post-pilot intervention is not a general architecture result.

Decision / next boundary: Retain the persistence/distractor tests; no rerun.

Primary source file(s): NSS_Research_and_Architecture_Chat_Handoff_v1.0.md

4.2 Q002

Status: COMPLETED_DIAGNOSTIC

Evidence: Executed study

Specific question

Can addressed memory know both a value and when nothing is known?

System: Addressed writable state with 4 addresses, 8 values + UNKNOWN; soft-state, hard-gate, full-history attention, and exact/belief controls.

Methodology: Evaluated clean and corrupted admission/retention through up to 4,096 distractors; separated write admission from read semantics and missing-value behavior.

Main result / key metrics: Wider-prepared soft state, calibrated hard gate, and exact controls retained clean records at 100%; short-prepared soft state failed UNKNOWN at longest gap; full-history cross-attention failed competence in all 5 seeds.

Checklist result: Prepared/gated versions could retain records; short preparation and poorly calibrated admission failed.

Interpretation / limits: Threshold calibration used labeled admission examples; does not establish a universal hard-gate advantage.

Decision / next boundary: Reuse UNKNOWN and event-admission distinctions.

Primary source file(s): NSS_Research_and_Architecture_Chat_Handoff_v1.0.md

4.3 Q003

Status: COMPLETED_MIXED

Evidence: Executed study

Specific question

Can noisy memories be repaired without inventing missing ones?

System: Nine-code numerical memory states; learned recurrent repair versus nearest-prototype and redundancy controls.

Methodology: Applied Gaussian shocks and repeated noise, then measured known-code recovery and preservation of UNKNOWN.

Main result / key metrics: After one sigma-1 shock recurrence improved known accuracy 65.01%→94.64% but UNKNOWN 71.33%→47.43%; long repeated noise drove recurrence to 100% known / 0% UNKNOWN while nearest-code was 100%/100%.

Checklist result: Denoising improved known values but could destroy UNKNOWN. Simple exact controls were stronger.

Interpretation / limits: Shows denoising can erase missingness; explicit presence metadata became necessary.

Decision / next boundary: Retain absence/novelty controls, not denoising as proof of truthful memory.

Primary source file(s): NSS_Research_and_Architecture_Chat_Handoff_v1.0.md

4.4 Q004

Status: COMPLETED_MIXED

4.6 Q006

Status: COMPLETED_BOUNDED

Evidence: Executed study

Specific question

Can a reader follow links through records with more thinking steps?

System: Structured record-hop and gated-hop readers, four-stage unshared reader, generic attention controls; 16 generated identities and relational records.

Methodology: Trained on four-link relations, evaluated up to eight-link depth with repeated computation and later with key/value noise.

4.7 Q007

Status: COMPLETED_MIXED

Evidence: Executed study

Specific question

System: Frozen relation readers with dictionary-conditioned repair, exact-nearest restoration, and intrinsic MLP repair.

14. Evidence, reproducibility, and source boundary

A pass/fail label never erases the measured size of an effect. Conversely, a large improvement does not erase failed safety, numerical, or whole-task criteria.

Development, confirmation, retrospective analysis, source-integrity checks, and third-party replication are different evidence classes.

Repeated events, histories, cue contexts, snapshots, or model branches are not automatically independent samples.

Exact software assistance is reported as software assistance, not learned model ability.

Test validity is reviewed separately from answer-key agreement. Administered evidence and raw answers should be retained whenever available.

Historical failures remain failed; later protocols can change prospectively but do not retroactively reclassify old gates.
